## 0. 数据前提声明（先看这条，否则后面的数字会被误读）

**本方案没有拿到任何客户自报数据。** 客户现状是：0 粉丝、0 内容、0 成交、App 上架状态未知、客单价未知。

因此：

1. 本文件中**所有收入/人数数字，一律标注为「假设推演」或「区间估算」**，含义是"在明确假设下的结构性推演"，**不是预测，更不是承诺**。
2. 客户目前没有可校准的基线，所以本方案不给"月入 X 万"这类结论。**给的是决策结构**——客户该测什么、拿到什么信号、信号指向哪条路。
3. 凡涉及"定价上调 / 付费产品上线 / 平台取舍"的动作，本文只给**推荐项 + 代价 + 可逆性判断**，**由客户拍板**。
4. 需要参照量级时，使用"结构性判断"表述并说明依据来源（P1 情报、本团方法论口径），**不编造行业均值**。

> 本方案与 P1 的合规前置警告（§2.0）完全一致，CTA 钩子已逐条规避广告法极限词与违规导流。

## 一、当前阶段判断

**当前阶段：冷启动（0 粉，无权重，零内容）**

| 判断项 | 事实 | 含义 |
|---|---|---|
| 粉丝量 | 0 | 抖音所有"需要账号量级"的变现口（品牌广告、带货、流量分成、付费课程挂载）**当前全部不可启动** |
| 专业积累 | **高**（Android 端侧 AI 工程实践者，产品是本人所造） | **客单价上限不由粉丝量决定，由专业度决定** → 他有资格直接做高客单服务，不需要等粉丝量 |
| App 状态 | 上架未知（可能只有 APK） | 决定"引流型 CTA 能不能挂链接"→ 必须 A/B 双轨设计 |
| 变现意图 | 客户明确"先不定，看数据再选" | 我的任务是**给一个能看数据的决策结构**，不是逼他现在选 |

**核心结论（一句话）**：

> 冷启动期他唯一"不被阻塞"的路径是 **服务承接**（卖他的时间和专业判断，不依赖 App 上架、不依赖粉丝量、不依赖许可核实）。
> 所以：**30 天不设计任何硬变现动作，只做"信号采集"；第一个可能的收入点，导向服务承接。**

## 二、变现路径全景（5 条可比）

> 每条都按 6 个字段拆解。**「可逆性」是本次最关键的判断字段**——不可逆的动作（如开课、收钱上线）一旦做了就回不了头，必须最后做、且由客户拍板。

### 路径 A — 知识付费（教"安卓离线 AI / 本地 TTS 落地方法"：专栏 / 课程 / 付费社群）

| 字段 | 判断 |
|---|---|
| 启动门槛 | 抖音端挂载付费课程需相应资质；更重要的是**信任门槛**——观众要先认"这个人懂"才买课。0 粉阶段无信任来源 |
| 最快回款周期 | 从 0 起，**第 6–10 周**（先有内容沉淀信任，才可能出单） |
| 天花板 | 假设推演：取决于信任沉淀速度与选题精准度。教育类内容天花板高，但**起量最慢** |
| 与身份契合度 | 高（他确有方法论）。**但 P1 已明确"教部署/教程向内容在抖音受众不买"，且会污染账号标签** |
| 主要代价 | 结构化成课 + 录课 + 答疑，交付成本高；**账号会被算法判成"教程号"，后续卖不了别的** |
| **可逆性** | **不可逆** — 一旦公开开课，"教育号"标签钉死，很难退回场景号/人设号 |

**一句话否决（暂不做）**：用一个**不可逆**的动作，去赌一个 **P1 已验证"抖音受众不买"**的方向——赌注和赔率都不对。

---

### 路径 B — App 增值（付费版 / 定制语音包 / 会员 / 去广告）

| 字段 | 判断 |
|---|---|
| 启动门槛 | 需 **① App 可公开分发（上架或至少有稳定下载入口）+ ② 打通付费通道（应用商店内购或合规第三方支付）+ ③ Apache 2.0 与模型许可核实完毕** |
| 最快回款周期 | 技术上上线付费项 1–2 周即可；但**没有流量就没有收入**，实际首单要到 **第 4–8 周** |
| 天花板 | 假设推演：工具类付费依赖装机量，装机量依赖内容 → **天花板由内容流量决定，不由产品决定** |
| 与身份契合度 | **极高**（他本人是开发者，增值项他能直接做、别人抄不了） |
| 主要代价 | ① **许可合规未核实就收钱 = 把风险敞口直接暴露**；② 付费必须建立在用户已认可免费版之上，过早收费=杀鸡取卵；③ 退款/客服成本 |
| **可逆性** | **半可逆** — 付费项可下架，但**一旦收了钱，用户预期不可逆**（退不回纯免费心智） |

**一句话否决（暂不做）**：受"上架未知 + 许可未核实"**双重阻塞**，且变现顺序反了——**0 粉阶段先建工厂再找工人**，正确顺序是内容先跑通、再谈产品化。

---

### 路径 C — 服务承接（帮企业 / 个人部署离线 AI、定制语音方案）

| 字段 | 判断 |
|---|---|
| 启动门槛 | **极低** — **不需要粉丝量**。内容本身就是作品集：他能拍出"断网读完整本书"，就等于贴出了能力证明。只需"能被找到 + 能证明能力" |
| 最快回款周期 | **最短** — 若内容发出后出现主动询价，**第 3–6 周即可成单**（不需要大规模信任沉淀，一个精准高意愿用户就够） |
| 天花板 | 假设推演：客单价高（L3–L4 区间），但**单笔占用大量交付时间，不可规模化**；天花板受"他一周能投多少小时"限制 |
| 与身份契合度 | **极高** — 这是他"别人抄不了"的真本事，直接变现 |
| 主要代价 | ① **时间被交付吃掉**（做服务就没时间做内容）；② 企业单需发票/合同；③ 交付不好砸招牌，口碑风险高 |
| **可逆性** | **可逆** — 做一单就结束，不影响账号定位。（注：若公开"长期接单"，会持续吸引低质询价，消耗精力，这一点需管理） |

**一句话推荐**：见第三节——**这是我推荐的唯一第一条路径。**

---

### 路径 D — 平台流量分成（抖音创作激励 / 中视频计划等）

| 字段 | 判断 |
|---|---|
| 启动门槛 | 抖音流量分成的具体准入门槛（粉丝/播放/时长要求）**需客户在"抖音创作者中心"当场核实**，本文不引二手数字 |
| 最快回款周期 | 需先有稳定播放量，**第 4–8 周**可能出现第一笔（金额很小） |
| 天花板 | 假设推演：流量分成**单价结构性偏低**，属"顺手接住"的零钱，**不能作为主路径** |
| 与身份契合度 | 中（不需要额外能力，但也不放大他的核心优势） |
| 主要代价 | 几乎无（被动收益）。**但会诱导内容为完播率而变形**，可能牺牲人设一致性 |
| **可逆性** | **可逆** |

**一句话否决（不作路径）**：它是"顺手接住"的零钱，**不是一条路径**——把它当成路径会把注意力从"人"转移到"量"。

### 路径 E — 私域沉淀后转高客单（咨询 / 陪跑 / 代做）

| 字段 | 判断 |
|---|---|
| 启动门槛 | 需要一个**站内合规**的承接载体（抖音关注 / 粉丝群 / 评论区名单）。**注意：抖音站内导流有严格限制，直接留微信/二维码会限流** |
| 最快回款周期 | 第 4–8 周（先有私域，再有询价） |
| 天花板 | 假设推演：高客单、低数量 |
| 与身份契合度 | 高（卖的是他的专业判断） |
| 主要代价 | 时间；**合规（不得违规导流）**；需持续维护，否则私域沉睡 |
| **可逆性** | **可逆**（私域是资产，不做也不亏） |

**一句话否决（不单列为路径）**：**E 本质是 C 的"承接管道"，不是独立水源。** 它与 C 高度重叠，单列无独立价值 → 把 E 当作 **C 的落地方式**即可。

## 三、明确排序与唯一推荐（不模糊）

### 唯一推荐的第一条路径：**C — 服务承接（轻服务起步）**

**为什么是它（4 条同时成立，其它路径最多满足 2 条）：**

1. **唯一不被阻塞的路径。** B 被"上架未知 + 许可未核实"卡住，A 被"信任门槛"卡住，D 被"播放量"卡住。——**只有 C，今天就能启动**，因为它卖的是他的能力，不依赖任何外部前置条件。
2. **回款最快。** 不需要大规模信任，一个精准高付费意愿用户即可成单（第 3–6 周）。
3. **契合度最高且不可复制。** "Android 端侧 AI 工程实践者"是别人抄不了的身份，服务承接直接把这个身份折现。
4. **可逆。** 做一单不影响账号定位，试错成本最低——**在"客户还没想好走哪条路"的前提下，先走一条可退的路，是唯一理性的选择**。

**并且 C 有隐性价值**：用服务赚到的钱**反哺内容生产**（内容需要时间，服务提供现金流），形成"服务养内容、内容带服务"的正循环；同时 C 的询价行为，**会直接验证"高付费意愿人群是否存在"** ——这正是客户想看的"数据"。

**推荐姿势（关键）**：**不是让客户现在挂"接单"CTA**，而是——**让 C 成为"第一个收入自然流淌出来的方向"**：30 天只做内容与信号采集，当询价信号出现时，**把它接成 C 的单**。

**为什么不是其余四条（各一句否决理由）：**

- **A 知识付费** → 否决理由：用一个**不可逆**的开课动作，去赌一个 P1 已验证**"抖音受众不买教程"**的方向，且回款最慢。
- **B App 增值** → 否决理由：受**上架未知 + Apache 2.0 未核实**双重阻塞，且"先产品后流量"顺序颠倒——0 粉阶段应"先流量后产品"。
- **D 平台流量分成** → 否决理由：单价结构性偏低，是**零钱不是路径**，且会诱导内容为完播率变形、损伤人设。
- **E 私域高客单** → 否决理由：**它是 C 的承接管道而非独立路径**，与 C 重叠，单列无意义。

### 三轨并行判断（给客户拍板用）

| 动作 | 推荐 | 代价 | 可逆性 | 谁拍板 |
|---|---|---|---|---|
| 30 天只做内容 + 信号采集，不为变现改内容 | **强烈推荐** | 30 天内大概率 0 收入 | 可逆 | 客户 |
| 同步去核实 App 上架可行性 + Apache 2.0 许可 | **推荐（并行，不占内容精力）** | 少量核对时间 | 可逆 | 客户 |
| 现在就开课 / 现在就挂付费 | 不推荐 | 不可逆 + 违规敞口 | 不可逆 | 客户 |
| 现在就在抖音留微信导流 | **不推荐（违规边缘）** | 限流风险 | — | 客户 |

## 四、前 30 天验证顺序（逐日 · 拿不到信号不进入下一步）

> **总原则**：冷启动期，**内容侧配比（引流 70% / 信任 20% / 转化 10%）不动**。变现设计只做一件事：**在每条视频 15–20 秒的 CTA 位，埋下"信号采集器"**。

| 时段 | 该做什么 | 拿到什么信号才进入下一步 |
|---|---|---|
| **D1–D3** | 账号搭建（头像/简介/封面按视觉基线）。简介**只放定位，不放任何 CTA**（此刻无可承接物）。发布 **Top1 选题**（飞行模式读完整本书） | 无需信号，先跑通发布流程 |
| **D3–D7** | 连发 **3 条 A 组断网实测**（#1 / #6 / #9），每条 CTA 位埋"求评论"类钩子（见第六节）。**不做任何导流** | **信号 1**：是否出现 ≥1 个独立用户在评论区表达"想要 / 怎么弄" |
| **D7** | **第一次信号读取** | 有"想要" → D8 起加码同类钩子；3 条全无"想要"且播放低 → **换钩子（回内容侧），不动变现** |
| **D8–D14** | 加发 **1 条信任型**（#16 程序员人设）。观察**主页访问量**与**关注转化** | **信号 2**：主页访问→关注的转化率是否被这条信任型内容拉高 |
| **D14** | **第二次信号读取** | 信任底座成立（有人因"这人懂"而关注）→ 进入 D15；不成立 → 补信任型内容，延后转化型 |
| **D15–D21** | 发 **1 条转化型**（#8 会议录音 或 #5 隐私对照）。这是**筛高付费意愿**的内容 | **信号 3（最关键）**：是否出现**主动询价 / 主动请求承接**（私信或评论） |
| **D21** | **第三次信号读取** | 见第五节判定树 |
| **D22–D30** | 按信号分流：① 有询价 → 接成 C 的第 1 单；② 有"下载/装机"密集询问 → 推进 B 轨（先解上架+许可）；③ 只有播放没"想要" → 回内容侧换钩子 | 产出**一条路径判定结论** |

## 五、30 天最小验证信号与判定口径

> 零基础账号 **30 天内不可能完成变现闭环**。所以 30 天的目标**不是"赚到钱"**，而是拿到**一个足以判断"该走哪条路"的信号**。

### 5.1 唯一关键信号：**"主动询价信号"**

**定义（口径必须精确，否则会被点赞收藏的数字骗到）：**

> **主动询价信号** = 用户**在未被 CTA 硬推的情况下**，主动表达「我想要 / 怎么弄 / 能帮我做吗 / 多少钱」的行为。
> **计数单位 = 独立用户数（去重），不是评论条数。** 同一个用户刷 10 条评论算 1。

**为什么是它，而不是点赞/收藏/播放：**

- 点赞收藏只证明"内容好看"，**不证明"愿意付钱"**（P1 的青青王样本已证明：收藏率 ≫ 点赞率，需求真实但传播弱）。
- **只有"主动要求"，才证明付费意图**。这是从"观众"到"客户"的分水岭。
- 它同时能**反向校准客单价**：客户可以在回复询价时**先试探报价**（"这个我一般是 XX 起做的"），用对方的反应反推市场能接受的价格带。

### 5.2 判定树：该加速 / 该换路

| 30 天结束时观察到的组合 | 判断 | 动作 |
|---|---|---|
| **≥1 个独立用户主动询价** | ✅ **路径成立** | **加速走 C（服务承接）**：把询价接成第 1 单，同时继续内容引流 |
| 某条视频的"想要"评论密度**显著高于**其它 | ✅ 钩子有效 | **复制该钩子的结构**，加大同类投放 |
| 0 询价，但"下载/装机"询问密集 | 🔀 **该换路** | 人群要的是**产品**不是**服务** → 推进 **B 轨**（先解上架 + Apache 2.0） |
| 0 询价，无"想要"评论，但**完播率高** | 🔀 **CTA 错位** | 内容对、出口错 → **只换 CTA，不换路径** |
| 播放量**普遍低于预期**，无任何"想要" | 🔀 **钩子问题** | **回内容侧**，换钩子/换选题，**不动变现设计** |
| 播放高、涨粉好，但**完全无商业意图** | ⚠️ 人设风险 | 内容偏"娱乐化"，需补**信任型 + 转化型**把注意力引向需求 |
| 出现**大量"求下载"但 App 没上架** | ⚠️ 承接缺口 | 立即启动 **B 轨的"无链接承接"设计**（见第六节 B 轨专章），否则流量全浪费 |

### 5.3 阈值说明（为什么先不给数字）

- 客户现在**没有任何基线**，任何"应该有多少询价"的数字都是**编造**。
- 因此先给**结构判断**：**≥1 个独立主动询价 = 路径成立；0 = 未验证**。
- 30 天拿到第一份数据后，**再由 data-analyst 校准具体阈值**（这一步是团队协作接口，不在本方案内）。

## 六、CTA 钩子设计（★ 本次最关键交付）

> 视频脚本在 15–20 秒处预留了 `【CTA 位：待变现架构师填入】`。以下是**可直接粘贴**的钩子。
> **铁律**：语音/字幕**不得出现极限词**（100%/绝对/永久/唯一/第一）；**不得出现任何站外联系方式或诱导导流话术**。

### 6.3 B 轨专章：**没有下载链接时，30 天怎么承接流量而不浪费**

> 这是本次最容易做错的地方。**没链接 ≠ 流量白费**，关键是把"产品承接"换成"**内容承接 + 名单承接**"。

**核心思路：没链接的时候，唯一能留下的资产是「关注 + 评论名单」。**

| 承接层 | 具体做法 | 为什么合规 / 有效 |
|---|---|---|
| **① 追更承接** | 每条视频结尾统一埋"下一条讲什么"的预告钩子（如"下一条我演示怎么读你自己的 PDF"），把单次观看变成**追更预期** → 沉淀关注 | 站内、无导流、算法友好；关注是最抗风险的资产 |
| **② 评论名单承接** | 人工记录评论区/私信里表达"想要"的**独立用户**（截图或备注），形成一份**高意愿名单** | 为**上架后第一批精准触达**准备燃料；不涉及任何站外导流 |
| **③ 群承接（≥1000 粉后）** | 建抖音粉丝群，群内统一答疑、同步上架进度 | **站内合规**；群成员是抗流失的私域 |
| **④ 内容即承接** | 用"方法型"内容（如 #6 十秒测谎仪）替代"下载型"内容——**没链接就交付知识**，知识本身就是留存物 | 观众拿到价值就不亏；且方法型内容收藏率高，长尾强 |

**B 轨 30 天的正确目标（重新定义"不浪费"）：**

> 不是"攒了多少下载"（根本没链接），而是——
> **攒了多少条真实"想要"需求信号 + 沉淀了多少关注 + 名单里有多少高意愿用户**。
> 这三样，是上架后转化的**直接燃料**。**没链接的 30 天不是浪费，是在为"上架那一刻"蓄水。**

**B 轨统一口播模板（零基础期直接用）：**

```
15–20s【CTA】「没网它照样读完了。想要的说一声，
        我看看有多少人需要，够了我就把它整理出来 / 上架了第一时间告诉你。」
```

> 合规点：① 不承诺"私发给你"（暗示导流）；② 不出现"加我"；③ 用"评论区说一声 / 关注我"承接；④ 用"看看有多少人需要"把 CTA 变成**需求投票**，既是信号采集器，又是内容互动引擎。

## 七、阶梯产品线雏形（3 层）

> **原则**：三层**不是都要马上做**。每层的"作用"和"现在该不该做"分开标注。
> **所有定价 = 区间估算，需按客户实际能力与交付成本校准，且由客户拍板。**

| 层 | 建议产品 | 价格区间（区间估算） | 交付物 | **作用** | **现在该不该做** |
|---|---|---|---|---|---|
| **L1 低价** | **「离线听书 · 机型适配 + 参数配置包」** | **¥9.9–29.9** | 交付物为数字资料：机型↔模型对照表、TTS 语音/语速推荐参数、朗读不中断设置清单 | **筛选 + 首付费破冰**：把"想要"的人转成第一次付费用户，同时过滤出**真需求** | **信号出现后即可做**（有人问价就先上 L1）。**这是把"免费"变"付费"的最小动作** |
| **L2 中价** | **「你的手机 · 离线朗读落地包（含答疑）」** | **¥99–499** | **卖结果不卖教程**：按客户机型给出配置方案 + 一次性真人答疑（不教原理，只保证"能用"） | **利润主力 + 再筛一层**：承接 L1 里"想一步到位"的人 | **等 L1 验证出转化率后再做**（避免未验证就投入交付设计） |
| **L3–L4 高价** | **「企业 / 个人 · 离线 AI 部署与定制语音方案」**（可含 1v1 陪跑） | **¥999–4999 / ¥5000–100000** | 定制部署、落地陪跑、企业离线 AI 场景咨询 | **高利润 + 只服务少数人**：这是**客单价突破 5000 的关口**——从"卖技能"升到"卖决策与结果" | **等出现真询价后才做**（无人问就不做，避免自嗨） |

### 7.1 三层的作用链（为什么是递进而不是并列）

```
L1（9.9–29.9）→ 破冰 + 筛真需求        （承担：过滤，不指望赚钱）
      ↓ 转化（结构性参照：逐层转化约 18–25%，本团方法论口径，需按账号校准）
L2（99–499） → 利润主力 + 再筛          （承担：现金流）
      ↓
L3–L4（999+）→ 高客单 + 卖决策          （承担：利润天花板）
```

> **升级心法**：卖技能 → 卖方法 → 卖结果 → 卖决策。**L2 的关键是"卖结果"（我帮你配好），不是"卖教程"（我教你配）**——后者正是 P1 判定"抖音受众不买"的方向。

### 7.2 Apache 2.0 许可下需要额外注意的产品（见第九节详述）

- **L1/L2 若交付"Encourage 定制版 / 打包好的 APK"** → 需保留版权声明与许可文件，不得使用原项目商标。
- **"定制语音包"若打包了第三方 TTS 模型/音色** → 模型的**独立许可**必须单独核对（与 App 的 Apache 2.0 无关）。
- **L3 企业部署交付二进制** → 同上；若仅是"上门配置服务"，风险较低。

## 八、漏斗诊断口径（客户拿到第一份数据后怎么读）

> **月收入 = 流量 × 转化率 × 客单价 × 复购次数**。以下把这个公式**翻译成这个账号能测的东西**。

| 乘数 | 在这个场景下**具体指什么** | **怎么读** | 出问题时的改法 |
|---|---|---|---|
| **流量** | 抖音单条内容的**播放量 + 涨粉数** | 看"**每万播放涨粉效率**"（增量粉 ÷ 播放量），**不看绝对播放** | 播放低 = 钩子/选题问题 → **回内容侧，不动变现** |
| **转化率** | ① 视频→"想要信号"（询价独立用户数 ÷ 播放量）；② "想要"→付费 | 0 粉阶段**只能测第①段**，第②段要等有产品 | ②段差 = 信任不足或产品不匹配 |
| **客单价** | 客户每单收多少。**现在未知** | 一旦有询价，**主动试探报价**，用反应反推价格带 | 有人"想要"但无人问价 = 缺报价锚 → **上 L1 试水** |
| **复购** | 同一用户是否再买 / 续费 | 工具/服务多为一次性，**复购偏弱** → 早期权重最低 | 无人复购 = 交付价值不足或无续费理由 → **设计后续产品，而非降价** |

### 8.1 「哪个乘数出问题」速查

| 症状 | 问题乘数 | 动作 |
|---|---|---|
| 播放普遍低 | **流量** | 换钩子（回内容侧） |
| 播放高、评论区无"想要" | **转化率** | 改 CTA（给出口 / 展示产品） |
| 有人"想要"但没人问价 | **客单价** | 上 L1 产品，制造报价锚 |
| 有人买但无人复购 | **复购** | 设计后续产品（非降价） |

### 8.2 精力分配口径（必须告诉客户）

> **推荐配比：流量 40% / 转化率 20% / 客单价 20% / 复购 20%。**
> 若客户想 **100% 投流量**——**这是效率最低的打法**。理由：在四个乘数里，**流量是提升难度最高（3–6 个月见效）、可复利性最弱**的一项；而**客单价是提升难度最低（1–2 周见效）、可复利性最强**的一项。
> **把精力全压在流量上，等于把所有筹码放在最难动、最慢见效、最不复利的那一格。**

## 九、复购机制选型

| 机制 | 载体 | 适用前提 | 对这个账号的判断 |
|---|---|---|---|
| **订阅制** | 小报童专栏 / Newsletter | 能**稳定按周期**交付 | ⚠️ 客户当前**无稳定交付能力证明**，暂不推荐 |
| **会员制** | 知识星球 / 年卡 | **必须有持续交付能力** | ❌ **明确劝阻**（见风险提示） |
| **产品线递进** | L1→L2→L3 逐层转化 | 有清晰的产品梯度 | ✅ **推荐**：与第七节阶梯产品线天然契合，复购=向上买更贵的那层 |

- **推荐机制：产品线递进**（而非会员制/订阅制）。
- **交付能力要求**：本账号复购靠**"升级购买"**，不靠"按期续费" → 对**周期交付压力小**，适合当前"个人自研 + 时间有限"的状态。
- **风险提示（必须转达客户）**：**知识星球等会员制社区，连续 15 日未更新即视为未履行服务义务**。客户若无稳定日更/周更的交付能力，**坚决不要做会员制**，选买断制产品。

## 十、风险与合规

### 10.1 ⚠️ Apache 2.0 许可风险（客户需自行核实清单，本文**不做法**律结论）

**背景**：Encourage 是 Google AI Edge Gallery 的 fork，保留 Apache 2.0。Apache 2.0 **允许商用与闭源衍生**，但有条件。客户若做**闭源付费版**，**必须先去核实以下具体事项**：

| # | 需核实的事项 | 说明（为什么重要） |
|---|---|---|
| 1 | **是否随分发保留了原项目的 LICENSE 与 NOTICE 文件** | Apache 2.0 要求分发时保留版权声明、许可文本；原项目若有 NOTICE 文件需一并保留 |
| 2 | **是否已彻底"去 Google 化"——有无残留原项目商标/名称/logo** | **Apache 2.0 §6 明确不授予商标权**。用了原项目名称/logo 做宣传可能侵权 |
| 3 | **若修改了源码，是否标注"已修改"** | Apache 2.0 §4(b) 要求修改文件带显著变更声明 |
| 4 | **做了闭源衍生后，分发物中是否仍包含 Apache 2.0 许可文本 + 版权声明** | 闭源允许，但**许可与版权声明不能省** |
| 5 | **所用大模型权重（Gemma 等）的独立许可** | **模型权重有自己的使用条款（如 Gemma Terms of Use），与 Apache 2.0 无关，必须单独核对**——这是最容易漏的一条 |
| 6 | **若打包了高通 NPU / 其他 SDK** | 高通等厂商 SDK 通常有**单独的许可协议**，限制分发与商用方式 |
| 7 | **自定义语音包 / TTS 模型的音色授权** | 音色/声音数据可能有**独立授权**，商用需确认 |

> **我不替客户下法律结论。** 以上是**核实清单**。建议客户在"收费/分发"前，逐条对照，必要时咨询专业法律意见。

### 10.2 广告法红线（沿用 P1 §2.0）

- **禁绝对化表述**：不得出现"100% 安全""绝对不泄露""永久免费""万无一失""唯一""第一"等极限词。
- **不得暗示"手机上就绝对安全"** → 正确口径：**"数据不上传 / 原文不出手机 / 断网也能用"**（可验证的动作）。
- **健康/医疗文档一律脱敏**，只演示"文字转语音、不出机"，**不做任何医疗解读**。
- **AI 生成内容需标注**。
- **不编造"数据被偷"的恐怖结论** → 只讲可验证机制。

### 10.3 平台导流限制

- **不得**在视频/评论/主页留**站外联系方式（微信/二维码/手机号）**——会被限流。
- **B 轨承接一律走站内**（关注 / 粉丝群 / 评论区名单）。
- **不设计任何违规导流话术**（如"想要的私我""加 V 领资料"）。

### 10.4 税务与平台数据

- **如实申报**。2026 年起平台数据与税务系统直连、按季报送收入明细，**走私户/空壳工作室已被明确打击**。
- 合规建议只有一条：**如实申报**。不建议任何"规避监管的技巧"。

### 10.5 收入集中度风险

- 单一收入来源占比应 **≤40%**。
- 本账号初期几乎 100% 依赖"内容→服务"单点 → **一旦有收入，要主动提示客户拓展第二来源**（如内容流量分成、L1 产品），避免单点风险。

### 10.6 不承诺收益（重复强调）

- 本文件所有数字均为**假设推演 / 区间估算**，**不构成收益承诺**。
- 客户现无自报数据，一切估算建立在"零基础起步"这一事实上，属**假设推演而非预测**。
