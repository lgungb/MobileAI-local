# 02 · 构建与工具链

本文只讲**怎么构建、工具在哪、有什么约定**。

## 1. 环境要求

- **JDK 21**：本机路径 `C:\Program Files\Java\jdk-21.0.12.1`（AGP 8.13 / Gradle 9.2.1 要求）。
  若系统 `JAVA_HOME` 未设置，构建前手动设：
  ```bat
  set JAVA_HOME=C:\Program Files\Java\jdk-21.0.12.1
  ```
- **Android SDK**：`local.properties` 已写 `sdk.dir=D:\Android\Sdk`。
  构建需要已安装 `platforms;android-36`（compileSdk=36）与对应 build-tools；本机已具备。
- **Gradle**：由 wrapper 提供（`gradlew` / `gradlew.bat`），版本 9.2.1。
  首次运行会读 `gradle/wrapper/gradle-wrapper.properties` 的腾讯镜像分发 zip（本机已缓存）。

## 2. 构建命令

在工程根目录 `D:\AndroidWork\SeAI_Encourage` 执行：

```bat
gradlew.bat assembleRelease --offline
```

- `assembleRelease` 产物：`app\build\outputs\apk\release\app-release.apk`
- 需要 debug 包：`gradlew.bat assembleDebug --offline`
- 装到设备：`adb install -r app\build\outputs\apk\release\app-release.apk`

> 也可用 `./gradlew`（Git Bash / sh）。工程只打包 `arm64-v8a`（见 app/build.gradle.kts ndk abiFilters），
> 12.0+ 设备均为 64 位 ARM，无需其他 ABI。

## 3. 离线构建约定（硬性约定）

1. **必须 `--offline` 构建**：本机环境不希望构建过程联网拉全量依赖。
2. **不要删除缓存**：以下目录是离线可用性的关键，删了将无法离线构建：
   - `%USERPROFILE%\.gradle\caches\`（依赖 jars / modules-2 / transforms）
   - `%USERPROFILE%\.gradle\wrapper\dists\`（Gradle 9.2.1 分发）
   - 本机 `D:\Android\Sdk` 的 platforms/build-tools
3. 若某次改动引入了仓库中不存在的新依赖且缓存里没有 → `--offline` 会失败；
   此时需先让依赖可用（联网预取一次或手动放缓存）再回归离线构建。

## 4. 内存与守护进程约定（硬性约定）

构建会拉起**多个独立 JVM**（Gradle 守护进程、Kotlin 编译守护进程、worker），
内存要**按份数**算，不是只算 `-Xmx` 那一个值。

`gradle.properties` 当前配置：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `org.gradle.jvmargs` | `-Xmx1536m` | Gradle 守护进程堆上限 |
| `kotlin.daemon.jvmargs` | `-Xmx1024m` | Kotlin 编译守护进程堆上限（**另一个 JVM**） |
| `org.gradle.workers.max` | `1` | 并行 worker 数（worker 也是独立 JVM） |

**规则**：

1. **构建结束后必须立刻执行 `.\gradlew.bat --stop`**。守护进程不会自动及时退出，
   常驻期间照样占内存。
2. **不要同时开多个构建**。多方并发会产生多个守护进程互抢文件锁，
   表现为「日志停在半路，既无 BUILD SUCCESSFUL 也无 BUILD FAILED、进程消失」。
   遇到这种情况先 `--stop` 清干净再重跑。
3. 可用 `.\gradlew.bat --status` 查看当前守护进程；`IDLE` 表示空闲可复用，`STOPPED` 是僵尸记录。
4. **不要上调上述内存上限**——本机需要在构建时保留可用内存给其他工作。

## 5. 依赖在哪里

| 依赖类型 | 位置 |
| --- | --- |
| 版本目录（集中管理版本） | `gradle/libs.versions.toml` |
| Maven 仓库（settings.gradle.kts） | 阿里云镜像(google/central/gradle-plugin) + google() + mavenCentral() |
| 本地 AAR | `app/libs/sherpa-onnx-1.13.4.aar`（app/build.gradle.kts 用 `implementation(files(...))` 引入） |
| native 库 | `app/src/main/jniLibs/arm64-v8a/`（自动打包） |
| proto 编译 | protobuf 插件按 `app/src/main/proto/` 生成 lite 代码 |

> `app/libs/sherpa-onnx-1.13.4-rknn.aar` 是瑞芯微 NPU 专用版，本机（高通 SM8750）**不用**；
> 已被 `.gitignore` 忽略，也不进 APK。

## 6. 关键 Gradle 参数（app/build.gradle.kts 现状）

- `namespace` / `applicationId`：`com.encourage.app`
- `compileSdk`：36；`targetSdk`：36；`minSdk`：31
- `versionCode` / `versionName`：**每次可构建的提交 +1**（末位递增），使 APK 版本与提交一一对应。
  查当前值看 `app/build.gradle.kts`。
- Java/Kotlin target：11（jvmTarget=11）
- release：`isMinifyEnabled=false`（不做代码混淆裁剪，便于调试与日志定位），签名用 debug 签名
- `packaging.jniLibs.useLegacyPackaging=true`：native 库解压到文件系统，供 LiteRT NPU 后端经 `nativeLibraryDir` 找到
- 强制 coroutines 1.9.0（对齐 litertlm 0.16.0，避免 `SendChannel.close` NoSuchMethodError）

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| `JAVA_HOME is not defined correctly` / 找不到 java | 设置 `JAVA_HOME` 为 JDK 21 |
| `--offline` 报找不到某依赖 | 该依赖不在本机缓存；需预取后重试 |
| SDK 找不到 / `platform android-36` 缺失 | 检查 `local.properties` 的 `sdk.dir` 与 SDK 安装 |
| 日志停在半路、无 BUILD 结论 | 守护进程互抢；先 `gradlew --stop` 再重跑 |
| 构建时机器内存吃紧 | 确认 `gradle.properties` 上限未被上调；构建后执行 `--stop` |
| 语音没声音排查 | logcat 过滤 `AGSpeechManager` |
| Kotlin 编译报 `Unresolved reference` 但代码看着没问题 | 多为**漏 import**。注意 `val ... by` 只需 `getValue`，`var ... by` 还需要 `setValue` |
