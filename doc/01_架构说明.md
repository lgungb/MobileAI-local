# 01 · 架构说明

本文说明**代码怎么组织、关键链路怎么走、每个现有模块是干什么的**。不含需求分析。

## 1. 工程形态

单模块 Android 工程（`settings.gradle.kts` 只有 `include(":app")`），
Kotlin + Jetpack Compose + Hilt。入口类：

- `com.encourage.app.GalleryApplication`：`@HiltAndroidApp` 的 Application，
  启动时设全局未捕获异常处理器（写入 DebugLog）、设置 `ADSP_LIBRARY_PATH`（骁龙 NPU/DSP 找 so），
  初始化本地服务等。
- `com.encourage.app.MainActivity`：单 Activity + Compose 导航。
- `com.encourage.app.GalleryApp` / `GalleryAppTopBar`：顶层 UI 框架。
- 导航图：`ui/navigation/GalleryNavGraph.kt`。

### 关键数据流（配置持久化）

`proto/*.proto`（生成 protobuf-lite）→ DataStore `.pb` 文件 → `DataStoreRepository` /
各领域 Repository（`VoiceSettingsRepository`、`ApiProviderRepository`、`TimedTaskRepository` 等）
→ `StateFlow`/`Flow` → Compose 界面。

## 3. 关键链路

### 3.1 本地推理（默认路径，100% 端侧）

```
UI (LlmChatScreen / AgentChatScreen …)
  → LlmChatViewModel（不区分来源）
  → AgentRuntimeExecutor.executeStream()
      ├─ 组装 AgentExecutionContext（模型、Skill、Tool、MCP、权限通道）
      ├─ LlmModelHelper.initialize(model)   // LiteRT-LM / AI Core
      ├─ LiteRT-LM 推理（tool calling 由 ToolDispatcher 调度）
      └─ Flow<AgentEvent>：StreamToken / Thinking / ToolCall / 完成…
UI 以「打字机」渲染增量，支持停止、历史、导出
```

### 3.2 云端 API（显式开关的增强项）

```
UI → LlmChatViewModel → RemoteOpenAICompatProvider.streamChat(config, turns)
  → Ktor HTTP POST OpenAI 兼容 /v1/chat/completions（SSE 流）
  → 产出与本地完全相同的 Flow<AgentEvent>（含 thinking 映射 reasoning_content）
```

开关与多套配置存在 Settings proto：`use_remote_api` 默认 false（本地优先），
`api_providers` 列表 + `active_api_provider_id`。

### 3.3 本地 API Server（局域网调用本机端侧模型）

```
LocalServerService（监听配置）→ LocalApiServer.start()
  Ktor CIO 监听端口 → POST /v1/chat/completions（OpenAI 格式，stream=SSE）
  GET /v1/models → 鉴权 Bearer Token → CORS
  请求到达时经注入的 modelProvider 拿当前模型 → AgentRuntimeExecutor 推理
```

### 3.4 TTS 双引擎

```
SpeechManager.speak(text)
  ├─ 系统 TTS（安卓内置，零依赖，中文随系统）
  └─ Sherpa-ONNX 离线（OfflineTtsEngine：加载 <externalFilesDir>/tts/<packId>/
        model.onnx → PCM → AudioTrack 播放；语音包由 VoicePackDownloader 下载解压）
引擎选择由 VoiceSettingsRepository 持久化；离线引擎未就绪自动回退系统 TTS。
朗读入口：对话气泡「朗读」按钮、语音设置「试听」、定时任务触发提醒。
```

### 3.5 定时任务

```
TaskCenter 增删改 → TimedTaskRepository → TaskScheduler（AlarmManager 精确闹钟）
触发 → NotificationReceiver → 系统通知 + SpeechManager 朗读任务内容
重复任务触发后按星期掩码推进下一次；开机由 BootReceiver 调 rescheduleAll()
```

## 5. 代码改动指南（怎么改）

- **加一个端侧可下载模型**：改 `assets/model_allowlist.json`（或对应 allowlist 版本 JSON）。
- **加/改技能**：改 `assets/skills/<skill>/` 定义与 `skills/SkillManager`、`tools/*Tool`。
- **加 Agent 角色**：在 `assets/agents/*.json` 加定义，参考现有 4 个。
- **加云端 API 服务商**：参考 `data/api/RemoteOpenAICompatProvider`（OpenAI 兼容）；配置 UI 在 `ui/home/ApiProviderSettings.kt`。
- **改语音行为**：入口 `speech/SpeechManager`；引擎实现 `speech/OfflineTtsEngine`；
  排查「不出声」看 logcat 过滤 `AGSpeechManager`（N6-A 可观测性改造后错误会暴露到界面）。
- **加自定义任务页**：仿 `customtasks/*` 的 TaskModule + Screen + ViewModel 注册进导航。

> 只改现状：不要引入「用户想要但还没有」的需求分析性假设；PRD 内容请留在工程外讨论。
