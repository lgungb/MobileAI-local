# 01 · 架构说明

本文说明**代码怎么组织、关键链路怎么走、每个现有模块是干什么的**。不含需求分析。

## 1. 工程形态

单模块 Android 工程（`settings.gradle.kts` 只有 `include(":app")`），
Kotlin + Jetpack Compose + Hilt。入口类：

- `com.encourage.app.GalleryApplication`：`@HiltAndroidApp` 的 Application，
  启动时设全局未捕获异常处理器（写入 DebugLog）、设置 `ADSP_LIBRARY_PATH`（骁龙 NPU/DSP 找 so），
  初始化本地服务等。
- `com.encourage.app.MainActivity`：单 Activity + Compose 导航。
- `com.encourage.app.GalleryApp`：Compose 根，内部挂 `GalleryNavHost` 与低内存回调。
- 导航图：`ui/navigation/GalleryNavGraph.kt`。

> `GalleryAppTopBar.kt` 是改造前的遗留文件，当前**无人引用**，待后续清理（见 `04` 技术债）。

## 3. 关键链路

### 3.1 本地推理（默认路径，100% 端侧）

```
UI（会话页）
  → LlmChatViewModel（不区分来源）
  → AgentRuntimeExecutor.executeStream()
      ├─ 组装 AgentExecutionContext（模型、Skill、Tool、MCP、权限通道）
      ├─ LlmModelHelper.initialize(model)   // LiteRT-LM / AI Core
      ├─ LiteRT-LM 推理（tool calling 由 ToolDispatcher 调度）
      └─ Flow<AgentEvent>：StreamToken / Thinking / ToolCall / 完成…
UI 以「打字机」渲染增量，支持停止、历史、导出
```

### 3.2 云端 API（显式开关的增强项）

```
UI → LlmChatViewModel → RemoteOpenAICompatProvider.streamChat(config, turns)
  → Ktor HTTP POST OpenAI 兼容 /v1/chat/completions（SSE 流）
  → 产出与本地完全相同的 Flow<AgentEvent>（含 thinking 映射 reasoning_content）
```

开关与多套配置存在 Settings proto：`use_remote_api` 默认 false（本地优先），
`api_providers` 列表 + `active_api_provider_id`。

### 3.3 本地 API Server（局域网调用本机端侧模型）

```
LocalServerService（监听配置）→ LocalApiServer.start()
  Ktor CIO 监听端口 → POST /v1/chat/completions（OpenAI 格式，stream=SSE）
  GET /v1/models → 鉴权 Bearer Token → CORS
  请求到达时经注入的 modelProvider 拿当前模型 → AgentRuntimeExecutor 推理
```

### 3.4 TTS 双引擎

```
SpeechManager.speak(text)
  ├─ 分句切块（splitIntoChunks，按标点 + 1000 字上限）
  ├─ 滑动队列逐块朗读，onDone 续读下一块（解决长文本被截断、读不完）
  ├─ 系统 TTS（安卓内置，零依赖，中文随系统）
  └─ Sherpa-ONNX 离线（OfflineTtsEngine：加载 <externalFilesDir>/tts/<packId>/
        model.onnx → PCM → AudioTrack 播放；语音包由 VoicePackDownloader 下载解压）
引擎选择由 VoiceSettingsRepository 持久化；离线引擎未就绪自动回退系统 TTS。
```

### 3.5 定时任务

```
任务中心 增删改 → TimedTaskRepository → TaskScheduler（AlarmManager 精确闹钟）
触发 → NotificationReceiver → 系统通知 + SpeechManager 朗读任务内容
重复任务触发后按星期掩码推进下一次；开机由 BootReceiver 调 rescheduleAll()
```

### 3.6 会话记录（特调）链路【2026-09 新增】

会话列表改造（T01~T06）把「一次对话用什么模型、什么提示词、什么参数」从
**per-task 全局**下沉为**per-record（每条记录独立）**。

```
列表页 ConversationListScreen
  ├─ 按 types 过滤（对话 Tab：CHAT/IMAGE/AUDIO；功能 Tab：AGENT）
  ├─ 点条目 → touchLastUsed → onProfileClick
  └─ 右下角「+」→ createNewConversation(taskId, type)
        → pickDefaultModel（优先已下载，否则第一个）
        → ConversationProfileRepository.createProfile(...)  // 返回带 id 的记录
        → openProfile(profile)

进入会话页 route_model/{taskId}/{modelName}?profileId=…&type=…
  → CustomTaskDataForBuiltinTask.profileId / conversationType
  → LlmChatTask.MainScreen：LaunchedEffect 里 getProfileFromStore(profileId)
  → viewModel.bindProfile(profile, task, model)
        ├─ 提示词：profile.systemPrompt 优先，为空回退 task 全局默认
        └─ 采样参数：id → label 映射后写入 model.configValues（见下方陷阱）

改提示词 → applySystemPromptChange
  → 已绑定记录 ⇒ 写入该记录（ConversationProfileRepository.updateSystemPrompt）
  → 未绑定记录 ⇒ 写回全局 system_prompt_$taskId（旧行为，作为默认值保留）
```

**数据关系**：`ConversationProfile` 1 : N `ChatSessionProto`（靠 `ChatSessionProto.profile_id` 关联）。
删除记录会**级联删除名下会话**，并清理 `cacheDir` 里的 `img_` / `audio_` 缓存文件。
旧会话通过**幂等的惰性迁移**归入默认记录（标记 `profiles_migrated`）。

**⚠️ 采样参数键名陷阱（改这块代码前必读）**

| 侧 | 键 | 例 |
| --- | --- | --- |
| 运行时读取 `Model.getTypedConfigValue`（`data/Model.kt:408`） | `ConfigKey.label` | `TopK`、`Temperature` |
| 记录存储 `ConversationProfile.configValues`（`:102`） | `ConfigKey.id` | `topk`、`temperature` |

两者**不一致**，直接把记录的 map 塞进 `model.configValues` 会**静默失效**（读不到值、不报错）。
正确做法：`LlmChatViewModel` 里的 `PROFILE_CONFIG_KEYS` 白名单 + 双向映射表
（由 `ConfigKey` 对象 `associate { key.id to key.label }` 派生，避免字符串漂移），
写入时再按 `valueType` 做 `String → Float/Int/Boolean` 转换，转换失败跳过并记日志。

> 补充：`ConfigKey.label` 虽名为 label，实为固定英文常量
> （`ConfigKey("topk", "TopK", R.string.config_label_topk)` 第二参是常量、第三参才是展示资源），
> 用作键稳定且不受语言影响。

### 3.7 模型实例生命周期【2026-09 调整】

现状策略是**加载后保活**，只在三种情况释放：

1. **切换模型**（`ChatView` 的 `onModelSelected`、`GalleryNavGraph` 的切页逻辑）
2. **系统低内存**：`GalleryApp` 注册 `ComponentCallbacks2`，
   `onTrimMemory(level >= TRIM_MEMORY_MODERATE)` 或 `onLowMemory()` 时调 `cleanupAllModels()`
3. **删除模型**：`ModelManagerViewModel.deleteModel` 删除前先 `cleanupModel`

**不再**在退出会话页时销毁模型（T05 前的行为），**也**不因为单纯转后台而释放
——否则"保活"失去意义，用户切走再回来又要重新加载数 GB 权重。

> 例外：`LlmSingleTurnScreen`（Prompt Lab）仍保留退页清理。它是横向 pager
> **多模型对比**场景，内存语义与「会话列表 + 单模型保活」不同，改动风险高、收益低，留作后续专项。

## 5. 代码改动指南（怎么改）

- **加一个端侧可下载模型**：改 `assets/model_allowlist.json`。
- **加/改技能**：改 `assets/skills/<skill>/` 与 `skills/SkillManager`、`tools/*Tool`。
- **加 Agent 角色**：在 `assets/agents/*.json` 加定义。
- **加云端 API 服务商**：参考 `data/api/RemoteOpenAICompatProvider`；配置 UI 在 `ui/home/ApiProviderSettings.kt`。
- **改语音行为**：入口 `speech/SpeechManager`；排查看 logcat 过滤 `AGSpeechManager`。
- **加/改会话记录字段**：改 `proto/conversation_profile.proto`（用**全新字段号**保证向后兼容）
  → `data/conversation/ConversationProfile.kt` 映射 → `ConversationProfileRepository`。
- **加一个底部 Tab**：改 `ui/navigation/BottomNavBar.kt` 的 `AppRoutes` / `BottomTab`，
  并在 `GalleryNavGraph` 里加 `composable`。只有顶层路由才显示底栏（判定在 `AppRoutes.isTopLevelRoute`）。
- **加自定义任务页**：仿 `customtasks/*` 的 TaskModule + Screen + ViewModel 注册进导航。
