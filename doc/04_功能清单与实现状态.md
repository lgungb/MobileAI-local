## 二、核心能力逐项状态

### 1. 端侧本地推理（✅）
- **代码**：`runtime/LlmModelHelper.kt`（LiteRT-LM）、`runtime/aicore/AICoreModelHelper.kt`、`agent/DefaultAgentRuntimeExecutor.kt`、`data/DownloadRepository.kt`（模型下载）。
- **现状**：本地模型经 LiteRT-LM 引擎跑在 NPU；骁龙 SM8750 打通。Gemma 4 E2B 16K 流畅 / 32K 可用。
- **说明**：UI 生成链路在 `ui/llmchat/`、`ui/llmsingleturn/`，通过 `agent/` 的事件流与渲染层解耦。

### 2. 云端 OpenAI 兼容 API（✅）
- **代码**：`data/api/ApiProviderRepository.kt`（多套配置持久化、默认本地优先）、`RemoteOpenAICompatProvider.kt`（SSE 流式，输出与本地同构 `AgentEvent`）、`data/api/ApiSecretCipher.kt`（密钥加密）。
- **现状**：可配多套 BaseURL+Key+模型，对话页顶部「来源条」三档切换（自动/本地/云端）——即 M7「推理来源切换」。
- **提示**：联网是显式开关；"本地优先、云端增强"。

### 3. 本地 API Server（✅）
- **代码**：`data/server/LocalApiServer.kt`（Ktor embedded CIO）、`LocalServerRepository.kt`。
- **现状**：局域网内暴露 OpenAI 兼容端点，可被外部设备/软件调用本地模型；设置界面管端口/Token。

### 4. 语音朗读（🟡）
- **代码**：`speech/SpeechManager.kt`（双引擎调度）、`speech/OfflineTtsEngine.kt`（sherpa-onnx + AudioTrack，native 仅后台线程）、`speech/VoicePackDownloader.kt`、`ui/home/VoiceSettings*.kt`（语音设置页）。
- **现状**：系统 TTS + 可选离线语音包（ModelScope/hf-mirror/GitHub 多源）。语速/音调/角色可调。
- **已知问题**：曾有"有界面不出声"——根因是 Android 11+ 包可见性缺 `<queries>` 声明 + SDK 37>设备 API 36，已在原工程修复（补 `queries`、SDK 降至 36）。**需在新工程真机复测确认出声**。
- **缺口**：离线语音包需用户自行准备/导入（引导已加）；多角色音色与语气标签的精细选择空间仍可扩展。

### 5. 定时任务 + 语音唤醒（✅）
- **代码**：`data/tasks/TaskScheduler.kt`、`TimedTaskRepository.kt`、`TaskAiInvoker.kt`、`notifications/`、`ui/tasks/`。
- **现状**：AI 可通过工具创建定时任务（"明天 8 点叫我"），用户可在任务中心编辑/暂停/删除/立即执行；触发时通知 + 可选朗读。开机恢复已做。
- **注意**：国产 ROM 杀后台是最大风险；精确闹钟需用户授权 + 关闭电池优化（引导在 `ui/tasks/`）。

### 6. 对话体验（✅）
- **代码**：`ui/common/chat/ChatView.kt`、`ChatPanel.kt`、`MessageActionIcon.kt`、`ChatExportHelper.kt`、`ChatMarkdownExporter.kt`。
- **现状**：消息可朗读/复制/单条保存/删除；长按多选批量删；会话导出 Markdown/分享；模型自动命名对话。

### 7. Agent / Skill / MCP（✅/🟡）
- **Agent**：`agent/`（运行时）+ `customtasks/agentchat/`（管理器）+ `data/agents/`（定义读写）。内置 4 个（`assets/agents/`）。
- **Skill**：`skills/SkillManager.kt` + `tools/ToolDispatcher.kt` + `assets/skills/`。支持 SAF 导入/删除/运行 + URL/GitHub 加载。
- **MCP**：`mcp/McpServersProvider.kt` + MCP Kotlin SDK。
- **缺口**：Skill/Agent 的"精选/推荐市场页"未做（属演进项）。

### 8. Prompt Lab（🟡）
- **代码**：`ui/llmsingleturn/`（四类单轮模板）。
- **现状**：Free form / Rewrite tone / Summarize / Code 四类可用。
- **缺口（未满足）**：用户想**自定义选项**——如语气可增"高亢"等自建值、摘要长度/格式可自定义、代码生成维度可自定义、可保存"我的模板"。见下节设计。

### 9. 文件管理器 / 文本查看编辑（✅）
- **代码**：`data/filemanager/FileManagerRepository.kt` + `ui/filemanager/`（SAF 浏览/打开/编辑/查看/分享/删除/新建）。
- **用途**：管理模型文件、agent/skill 文件、导出的对话/图片等。

### 10. Mobile Actions / Tiny Garden（🟡，需求待拍板）
- **Mobile Actions**：`customtasks/mobileactions/` —— 语音控制手机（Intent），完全离线。用途：需要下载模型 + 部分操作需辅助功能权限；当前功能/使用条件需在 App 内向用户讲清。
- **Tiny Garden**：`customtasks/tinygarden/` —— 种花小游戏，依赖 FunctionGemma，模型国内难下载 → 点开不可用。
- **缺口/决策**：Tiny Garden 计划用**国产支持 Function Calling 的小模型（Qwen 系 LiteRT 版）复活**（演进项）。见下节。

## 三、未满足 / 缺口项的设计说明（演进方向，供后续开发）

> 这些是**已识别但尚未落地**的能力。设计方向来自产品决策记录，属于工程演进依据，不是承诺性路线图。

### 3.1 Prompt Lab 自定义（🟡→做）
**目标能力**：四类模板都能加"自定义预设值"并可保存成个人模板。
- 语气（Rewrite tone）：在预设（正式/轻松…）之外，允许用户新增自定义值，如"高亢"。
- 摘要（Summarize）：可自定义目标长度（短/中/长/自定义字数）、输出格式（要点/段落/表格）。
- 代码（Code）：可自定义语言范围、风格（注释/无注释）、目标（实现/解释/重构/测试）。
- 通用：每个可自定义字段 = "预设选项列表（可增删）+ 一个自由输入框"，结果拼进 Prompt。
**建议落点**：`ui/llmsingleturn/` 增一个"模板/自定义项"数据模型（本地持久化），UI 由"固定模板"升级为"模板 + 我的预设"两段式选择。

### 3.2 统一对话入口 / 能力收敛（⬜→做，方案 B+）
**背景**：目前各能力在首页以多张卡片分散入口；已设计为**一个统一对话容器 + 底部"能力选择器"**，
人点一次选能力（识图 / 听写 / AI 对话 / Agent / Skill…），不做 AI 自动意图路由。
- 顶部保留「推理来源条」（自动/本地/云端，M7），底部加「能力条」，二者正交。
- 首页收敛入口 7→4，保留识图/听写/快捷任务 3 个快捷直达，其余能力进对话页 + "更多"。
- **架构前置（R2）**：切换能力时的模型/上下文/ViewModel 生命周期需先定方案（避免重复初始化/串台）。
**参考设计稿**（原工程，迁移时未纳入）：`Super Encourage me/gallery/docs/14/15` 含 PRD 与界面规范。
**提示**：首次开工前请同步这几份设计稿进本工程 `doc/`。

### 3.3 语音 / 联网能力的"讲清用途"体验
**问题**：Mobile Actions、Tiny Garden 用户"不清楚怎么用、什么条件"。缺的不是功能，是**就地说明**。
**设计方向**：在功能入口卡片/页面内嵌「这是什么 / 需要什么前置（模型/权限）/ 举个用法」三层说明，
类比已有语音包的"导入引导"。数据源可放在 `assets/` 的 JSON，与代码解耦，便于维护文案（中英双语）。

### 3.4 帮助中心深化
**现状**：已有首页帮助卡片 + 帮助中心若干章节（快速开始/智能体/云端/本地服务/定时任务/基准/FAQ/隐私）。
**缺口**：逐页面内嵌"?"直达对应说明；首启 3 步引导。
**方向**：帮助文案按页面归口，新迭代把"更新对应帮助章节"纳入完成标准，防过期。

### 3.5 文生图（❌，演进项）
**现状**：无端侧文生图实现。历史 `MP_SCRAPBOOK` 是死代码（有常量、无功能注册）。
**方向**：端侧文生图依赖**能跑的小型 diffusion/quant 模型**（体积大、NPU/CPU 权衡复杂），
属高成本演进项，暂不纳入主线；若要占位，可先把 Scrapbook 转成"文生图画廊"容器，模型接入另议。

### 3.6 统一"模型参数说明"（B4）
**现状**：模型配置弹窗已有（`ui/common/ConfigDialog.kt` 等），但"每个参数配一个 ? 说明小按钮"未完整铺开。
**方向**：为 Max Tokens / Temperature / TopK / TopP 等在弹窗参数旁加 ? 按钮 → 弹通俗中文解释与调参建议。
属低难度补齐。

### 3.7 Skill/Agent 精选市场页（演进项，已留位）
**方向**：复用现有"从 URL/GitHub 加载 Skill/Agent"能力，加一个**精选列表页**（本地 JSON 配置即可），
为将来"推荐位/分类位/分发渠道"留货架结构。

## 四、已知技术债 / 待排查（写代码前先看）

1. **语音真机复测**：N6-A 的 `queries` + SDK36 修复需在 Android 16 真机验证出声。
2. **谷歌界面文案残留**：个别界面/字符串可能仍含 Google 相关文案或链接（点击后是否跳 Play 需查），属"去谷歌化"收尾项，建议逐页走查。
3. **Scrapbook 死代码**：`MP_SCRAPBOOK` 只有任务常量、无功能实现；要么删、要么转画廊占位。
4. **sherpa-rknn.aar**：`app/libs/` 里 26MB 瑞芯微专用 AAR 被 .gitignore 忽略（高通用不到），如需瘦身可直接删磁盘文件。
5. **worker/ 上游遗留**：`worker/AndroidManifest.xml` 等历史文件原样保留，不影响构建，可择机清理。
6. **端侧模型体积**：NPU LLM + 离线 TTS 语音包并存时的内存压力，需"按需加载、及时释放"。
