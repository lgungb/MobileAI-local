## 1. 设计原则与全局规范

### 1.1 核心设计原则
1. **先任务后装饰**：首屏先保证"用户知道能做什么、能立刻开始"，视觉层级服从任务层级。
2. **零误判的交互诚实**：能力由用户显式选择（方案 B+），不做 AI 自动路由；不可用能力**置灰 + 说明原因 + 给解决路径**，不静默禁用。
3. **离线卖点可见化**：任何联网动作（下载 Skill、调用云端 API）都要有**醒目的状态指示与首次提示**，颜色不是唯一信号（图标 + 文字 + 颜色三者并存）。
4. **说人话**：禁止"推理""Token 预算"等术语裸奔；必须时用括注解释；单句 ≤20 字。
5. **可访问性是基线不是补丁**：触控 ≥48dp、对比 ≥4.5:1、字体 200% 不裁切、TalkBack 可用、深/浅双主题。

### 1.2 色彩规范（基于 `ui/theme/Color.kt` 真实 token）

> 【事实】Encourage 沿用 Google 蓝主色与 Material 3 surface 层级。下列为真实值，可直接映射。

| 语义角色 | Light 值 | Dark 值 | 用途 |
|---|---|---|---|
| `primary` | `#0B57D0` | `#A8C7FA` | 主行动、选中能力 Chip、主入口高亮 |
| `onPrimary` | `#FFFFFF` | `#062E6F` | 主按钮文字 |
| `primaryContainer` | `#D3E3FD` | `#0842A0` | 选中态背景（能力条、来源条选中） |
| `secondary` | `#00639B` | `#7FCFFF` | 次级行动、链接 |
| `tertiary` | `#146C2E` | `#6DD58C` | **离线城市/可用/本地就绪**正向状态（绿色）【判断：复用 tertiary 作"本地可用"语义色，避免新造色】 |
| `error` / `errorContainer` | `#B3261E` / `#F9DEDC` | `#F2B8B5` / `#8C1D18` | 错误、失败、危险操作 |
| `surface` / `background` | `#FFFFFF` | `#131314` | 页面底色 |
| `surfaceContainerLow/…/Highest` | `#F8FAFD→#DDE3EA` | `#1B1B1B→#333537` | 卡片/抽屉/弹层层级 |
| `onSurface` / `onSurfaceVariant` | `#1F1F1F` / `#444746` | `#E3E3E3` / `#C4C7C5` | 正文 / 次要文字 |
| `outline` / `outlineVariant` | `#747775` / `#C4C7C5` | `#8E918F` / `#444746` | 边框、分隔、Chip 描边 |

**状态语义色使用规则（【判断】）**：
- 正向/可用/本地：**tertiary**（绿）。
- 警示/需联网/实验中：**secondary** 或 `tertiaryContainer` 配图标。
- 错误/失败/危险：**error**。
- 加载中：中性 `onSurfaceVariant` + 旋转指示器，**不单独用颜色承载**。
- **所有状态同时配图标 + 文字**，颜色仅作辅助（满足可访问性"颜色非唯一载体"）。

> 注：亮/暗主题下 `primary` 与 `onPrimary` 互换（light 深蓝底白字 / dark 浅蓝底深蓝字），所有组件须双主题校验。

### 1.3 字号规范（基于 `ui/theme/Type.kt`，Material 3 baseline + Nunito）

> 【事实】字体家族为 **Nunito**；类型刻度沿用 M3 baseline。下列为 M3 基准值区间，跨设备/缩放以 `sp` 为单位、随系统字体缩放。

| 角色 | M3 基准 (sp) | 本应用用途 | 200% 缩放后处理 |
|---|---|---|---|
| `displayMedium`(首页标题) | 45 | 首页大标题（已定制 48sp） | 允许换行，不限制单行 |
| `headlineSmall` | 24 | 页面标题、空状态标题 | 换行 |
| `titleLarge` | 22 | 对话框标题 | — |
| `titleMedium` | 16 | 卡片标题、Chip 文字 | 单行可省略 |
| `bodyLarge` | 16 | 正文 | 行高随缩放 |
| `bodyMedium` | 14 | 次要说明 | — |
| `labelLarge` | 14 | 按钮文字 | — |
| `bodySmall`/`labelSmall` | 12 | 灰字说明、徽标 | 不低于 11sp 实际显示 |
| `emptyStateTitle`(定制) | 37 / 16 | 空状态主/副标题 | 换行 |

> 【判断】**最小可读字号**：正文 ≥14sp（约 M3 bodyMedium），辅助说明 ≥12sp 但仅在非关键信息使用。中文在 12sp 下可读性边缘，辅助说明建议 13~14sp。
> 【假设】若产品要求更小辅助文字，需无障碍评审确认 ≥4.5:1 对比且 200% 不裁切。

### 1.4 间距规范（8dp 基准栅格，【判断：M3 推荐 4/8/12/16/24 节奏】）

| 间距 | 值(dp) | 用途 |
|---|---|---|
| xs | 4 | 图标与文字贴邻 |
| sm | 8 | Chip 内边距、控件间隙 |
| md | 12 | 同组元素间距 |
| lg | 16 | 卡片内边距、区块间距 |
| xl | 24 | 页面左右安全边距、大区块间距 |
| 2xl | 32 | 首屏主入口呼吸空间 |

圆角（【判断：与现有卡片一致】）：Chip 全圆角（pill，≥18dp 或 50%），卡片 12~16dp，对话框 28dp（M3 大圆角），底部面板 28dp 顶部圆角。

### 1.5 Elevation / 容器层级（【判断：用 surfaceContainer 层级替代阴影，符合 M3 与现有 fork 风格】）

| 层级 | 容器 | 典型承载 |
|---|---|---|
| 0 | `surface` | 页面底色 |
| 1 | `surfaceContainerLow` | 来源条背景条、输入区背景 |
| 2 | `surfaceContainer` | 卡片、列表项 |
| 3 | `surfaceContainerHigh` | 抽屉、下拉菜单、底部面板 |
| 4 | `surfaceContainerHighest` | 弹窗、Snackbar、气泡 |
| 浮动 | `+scrim` | 抽屉遮罩、对话框遮罩（黑 32~40% 不透明） |

> 优先用**色阶（surfaceContainer 层级）**区分浮层，而非重阴影；暗色主题下更需靠色阶而非阴影区分。

### 1.6 双语与可访问性基线
- **双语**：所有用户可见字符串提供 `values/`（默认英文）与 `values-zh/` 两版；英文通常比中文长 30~60%，**布局必须自适应**（按钮换行、Chip 横向滚动，禁止固定宽度截断）。
- **触控目标**：所有可点击元素命中区域 ≥48×48dp（视觉可更小，但 `Modifier.sizeIn(minWidth=48.dp, minHeight=48.dp)` 保证命中）。
- **对比度**：正文/图标 vs 背景 ≥4.5:1；大字号/图标 ≥3:1。
- **字体缩放**：系统最大 200% 下不裁切、不重叠、关键操作不被挤出屏幕。
- **TalkBack**：朗读顺序 = 视觉顺序（自上而下、自左而右）；所有非文本元素有 `contentDescription`；状态变化用 `LiveRegion` 或 `announceForAccessibility` 播报。
- **深/浅主题**：全部页面双版交付，暗色重点校验 surface 层级与 outline 对比。

## 2. 全局状态语言与组件约定

为保持一致性，定义跨页面复用的"状态视觉语言"（【判断】）：

| 状态 | 视觉语言 | 文字要求 |
|---|---|---|
| 空 | 居中图标(48dp, `onSurfaceVariant`) + 标题(emptyStateTitle) + 一行说明 + 主操作按钮 | 说"为什么空" + "下一步做什么" |
| 加载 | 行内旋转 `CircularProgressIndicator` 或骨架屏；主操作 disabled | 不阻断其余阅读 |
| 错误 | `errorContainer` 横条 + 错误图标 + 红字 + 具体原因 + 恢复操作 | 指出"哪错"和"怎么办" |
| 无权限 | 卡片内 `errorContainer` 提示 + 「去设置」按钮 + 一句隐私安抚 | 说明缺什么权限、去哪开 |
| 不可用(能力/项) | Chip/项 **置灰**(`outlineVariant` 描边 + `onSurfaceVariant` 文字) + 右上角小锁图标 + 点击弹气泡 | 气泡说"为什么不可用 + 怎么解决" |
| 成功 | Snackbar(短时) 或 `tertiary` 状态徽标；含结果 + 下一步 | 不只说"成功" |
| 联网操作 | 顶部 `secondary` 小条"正在联网…" + 首次弹窗确认 | 明示"在联网、传什么" |

**全局红色使用纪律**：error 仅用于真正的错误/失败/危险；不可与"实验中/需联网"警示（用 secondary/tertiary）混淆，避免告警疲劳。

### 3.1 P1 首页 Home（收敛后）

**核心任务句**：【事实/PRD】一位刚装上 Encourage 的新用户，在第一次打开应用时，需要立刻知道这个软件能做什么并开始第一次对话，因为我们要把"从打开到首次成功对话"的时间压到最短。

**信息优先级（L1/L2/L3）**：【事实】
- L1：「开始对话」主入口（唯一视觉焦点，首屏黄金位）+ 一句话产品说明（"完全本地运行的 AI 助手，不联网也能用"）。
- L2：3 个快捷直达（识图 / 听写 / 快捷任务，横向三等分小卡片，图标+4字标签）；使用说明入口卡（强化现有 `HomeHelpCard`）。
- L3：「实验室」折叠区（默认收起，带"实验性"徽标）；「全部能力」收纳进"更多"（保留现有分类 Tab+ViewPager 机制承载长尾）。

**低保真结构（文本线框）**：
```
┌─────────────────────────────┐
│ ☰            设置/帮助(右上) │  ← 抽屉把手 + 右上角入口
│                             │
│  完全本地运行的 AI 助手，     │  ← L1 产品说明(≤20字/行)
│  不联网也能用                │
│                             │
│  ┌───────────────────────┐  │
│  │   [ 开始对话 ]          │  │  ← L1 主入口(大按钮, primary)
│  │   通用对话 · 本地推理    │  │
│  └───────────────────────┘  │
│                             │
│  快捷直达                    │  ← L2 分组标题
│  [识图]  [听写]  [快捷任务]  │  ← 三等分小卡片(图标+4字)
│                             │
│  [ ℹ 查看使用说明 ]          │  ← L2 说明卡
│                             │
│  ▸ 实验室 (实验性)           │  ← L3 折叠, 默认收起
│                             │
│  更多 ▾                      │  ← L3 "全部能力"收纳入口
└─────────────────────────────┘
```

**主入口中英双版示意**：
```
中文：  [ 开始对话 ]          英文：  [ Start chatting ]
        通用对话 · 本地推理               General chat · On-device
```
> 【判断】英文 "Start chatting" 比中文"开始对话"略长但可控；副标题英文 "General chat · On-device" 约 22 字符，需允许换行或缩小至 labelSmall。主按钮用 `fillMaxWidth` 避免定宽截断。

**组件与字段规格**：
| 组件 | 用途 | 默认值 | 校验/依赖 |
|---|---|---|---|
| 主入口按钮 | 进入统一对话页(通用对话默认) | 文案"开始对话" | 无模型时变"先下载模型"→跳模型管理 |
| 产品说明文字 | 一句话价值主张 | `app_intro`(已改 Encourage 口吻) | 中英双版 |
| 快捷直达卡 ×3 | 识图/听写/快捷任务 直达 | 图标+4字标签 | 点击直达对应能力(预选) |
| 使用说明卡 | 打开帮助中心 | "查看使用说明" | — |

| 更多 | 展开"全部能力"分类 Tab | 默认收起 | 复用现有 ViewPager |

**完整状态矩阵**：
| 状态 | 触发 | 用户看到 | 可执行动作 | 数据保留 | 恢复路径 |
|---|---|---|---|---|---|
| 初始 | 首次启动已装模型 | 主入口高亮可点 + 说明区显示当前模型名 | 开始对话/快捷直达 | — | — |
| 加载 | 模型加载中 | 主入口显示进度环+"正在加载模型…"，可取消 | 取消加载 | — | 取消后回首页 |

| 部分 | 部分能力模型缺失 | 主入口可点；缺模型的快捷直达置灰+锁 | 走通用对话/去下载 | — | 下载后解锁 |
| 无权限 | 无 | 首页不依赖特殊权限 | — | — | — |
| 校验失败 | 无 | — | — | — | — |
| 网络失败 | 无(首页不联网) | — | — | — | — |
| 处理中 | 下载模型中 | 同"加载" | 取消 | — | — |
| 成功 | 模型就绪 | 主入口高亮 + 说明区显示模型名 | 开始 | — | — |
| 重复提交 | 连点主入口 | 去重：仅开一个对话页 | — | — | — |
| 过期 | 无 | — | — | — | — |

**响应式行为**：
- 360dp：主入口 `fillMaxWidth`；快捷直达三列等宽(各≈104dp)，标签 icon 上文字下，标签过长(如英文)换行或缩为 icon+两字。
- 420dp+：主入口可加大内边距；快捷直达卡可加副标题；"更多"展开后分类 Tab 横向翻页更宽松。
- 字体 200%：主入口文字换行不裁切；说明文字允许 3 行。

**可访问性**：
- 主入口命中 ≥48dp；快捷卡整卡可点(≥48 高)。
- 主入口 `contentDescription`="开始对话，进入本地 AI 助手"。
- 实验室徽标"实验性"同时有图标(⚗)+文字，非颜色唯一。
- 暗色：主入口 primary 在 dark 下为浅蓝底深蓝字，对比合格。

### 3.2 P2 统一对话页 UnifiedChatScreen

**核心任务句**：【事实】一位需要在一次会话中混用多种能力的用户，在先文字提问、再发图追问、最后让它总结的场景下，需要同一个页面内完成全部操作而不丢失上下文。

**信息优先级**：【事实】
- L1：消息列表（沿用 ChatView，不改）；输入框 + 发送按钮。
- L2：能力选择器（输入区上方横向 Chip）；M7 推理来源条（顶部，仅配置云端时显示）。
- L3：附件按钮（图片/音频/拍照）；M7 生成统计条（生成后显示）；右上角会话历史/配置。

**低保真结构（文本线框）**：
```
┌─────────────────────────────┐
│ ←  通用对话          历史 配置 │  ← 顶部: 返回 + 标题(=当前能力名) + 右上
├─────────────────────────────┤
│ [推理来源条 M7] 自动│本地│云端 │  ← L2 仅配置云端时显示(详见4.2)
├─────────────────────────────┤
│                             │
│   (消息列表 ChatView)        │  ← L1 主内容, 可滚动
│   用户: 帮我看看这段话        │
│   AI: …                     │
│                             │
├─────────────────────────────┤
│ [能力条 CapabilityBar]       │  ← L2 输入区上方(详见3.3/4)
│  通用│识图│听写│快捷任务│智能体│更多
├─────────────────────────────┤
│ ＋ [输入框………………]  [发送➤] │  ← L1 输入区
└─────────────────────────────┘
```

**组件与字段规格**：
| 组件 | 用途 | 默认 | 依赖 |
|---|---|---|---|
| 标题栏 | 显示当前能力名 + 返回 + 历史 + 配置 | 标题=能力名 | 沿用现有 |
| 来源条 | 选算力档位(自动/本地/云端) | 沿用 M7 | 仅云端配置时显示 |
| 消息列表 | 多轮消息 | 沿用 ChatView | — |
| 能力条 | 选能力(切 taskId) | 通用对话 | 见 3.3 |
| 输入区 | 文本+附件+发送 | 沿用 | — |
| 生成统计条 | 完成后 show token/s 等 | 沿用 M7 | — |

**完整状态矩阵**：
| 状态 | 触发 | 用户看到 | 可执行 | 数据保留 | 恢复路径 |
|---|---|---|---|---|---|
| 初始 | 新会话 | 中央显示当前能力引导语(随能力变) | 输入/选能力 | — | — |

## 4. 统一对话页 + 能力选择器深度设计（N6-1 核心）

> 本章最详细，因它是本次唯一新建主链路，且要协调顶部来源条(M7)与底部能力条(N6)的正交共存。

### 4.1 整体布局栈（自上而下）
```
[ 顶栏 ]     返回 + 当前能力名(=标题) + 历史 + 配置
[ 来源条 ]   M7: 自动 | 本地 | 云端   ← 仅配置云端API时显示
[ 消息区 ]   ChatView (可滚动, weight=1)
[ 能力条 ]   CapabilityBar (输入区上方, 横向Chip)
[ 输入区 ]   ＋ | 输入框 | 发送
```

### 4.2 来源条(顶) 与 能力条(底) 的关系与区分【判断，关键】

两者**正交共存**：来源条管"用什么算力"(自动/本地/云端)，能力条管"用什么能力"(对话/识图/听写…)。设计上用三重区分防混淆：

| 维度 | 来源条(M7, 顶部) | 能力条(N6, 底部) |
|---|---|---|
| 位置 | 页面顶部, 紧贴顶栏下 | 输入区上方, 紧贴输入 |
| 语义标签 | "算力档位" — 配信号/芯片图标 | "功能档位" — 无额外标签(上下文即能力) |
| 视觉响度 | **安静**：`surfaceContainerLow` 背景条 + `outline` 描边 Chip，选中=secondaryContainer | **响亮**：选中=primaryContainer(蓝)，未选=透明描边 |
| 显示条件 | 仅配置了云端 API 时出现 | 始终出现 |
| 切换影响 | 影响推理后端/速度/是否联网 | 影响 taskId/上下文 |

> 图示（文本）：
```
顶 ─ [来源条: 自动│本地│云端]  (灰底, 小chip, 安静)
    ───────────────────────
    (消息)
    ───────────────────────
底 ─ [●通用│识图│听写│快捷│智能体│更多]  (蓝选中, 响亮)
    ─ [输入…][发送]
```
- 颜色区分：来源条选中用 secondary 系(青蓝 `#00639B` 容器)，能力条选中用 primary 系(蓝 `#0B57D0` 容器)。两者色相接近但**明度/容器层级不同**，且位置天各一方，不会误读。
- 若未来来源条与能力条同时需强调，建议来源条保持安静以突出"用户当前在选能力"这一主任务（符合"先任务后装饰"）。

### 4.3 能力切换的交互细节
- **切换 = 切 `taskId`**，不重建对话页(复用同一 ChatView 与消息列表容器)。
- **上下文默认保留**（除单轮模式）：切到识图/听写/智能体时，历史消息保留在列表中；若已有历史与新能力语义可能不匹配，弹出轻提示"当前会话将沿用已有上下文，切换能力可能影响理解"，提供「切换并新建会话」选项（【判断：缓解 PRD R3 上下文混乱风险】）。
- **切到快捷任务(单轮)**：页面切为上下分栏(输入上/输出下)，顶部 `tertiary` 提示"此模式不保留上下文"，可手动关。
- **生成中禁止切能力**：所有 Chip 置灰，仅"停止"可用，避免中途切导致语义混乱（【事实/PRD】）。
- **记得上次选择**：非出厂默认记住用户上次能力，下次进统一页默认选中（通用对话为出厂默认）。

### 4.4 不可用能力的统一处理
- 缺模型的能力(如识图需多模态、智能体需FunctionGemma)：Chip **置灰 + 右上小锁图标**，点击弹气泡"需下载 XX 模型" + 「下载模型」按钮跳模型管理。
- 缺权限(听写需录音/识图需相册)：置灰 + 锁 + 气泡"需要XX权限，去设置开启" + 「去设置」。
- 不静默禁用，永远给"为什么 + 怎么办"。

## 5. 关键交互流程

### 5.1 切换能力时历史消息如何处理
```
用户点「识图」(生成未在进行)
  ├─ 当前为通用对话且有历史
  │    ├─ 弹轻提示: 沿用上下文可能影响理解?
  │    │    ├─ [继续, 保留上下文] → 切 taskId, 历史保留, 引导语更新为识图
  │    │    └─ [切换并新建会话] → 清空上下文, 新会话
  │    └─ (用户可在设置关此提示)
  └─ 当前为快捷任务(单轮)
       └─ 离开单轮: 提示"单轮不保留上下文", 切到多轮能力后开始新上下文
```
> 规则：【事实】多轮能力间切换保留消息；单轮↔多轮切换不保留；生成中禁止切。

### 5.2 模型切换
- 对话页"配置"→ Model configs 选本地模型；切换模型时若正在生成先停止。
- 来源条切"云端"需已配置外部 API，否则该档置灰+说明"未配置云端 API"。
- 模型切换不影响能力选择与历史(同能力换模型)。

### 5.3 来源切换（M7 复用）
- 自动/本地/云端 三档；仅"云端"涉及联网，首次选云端触发 P12 联网提示(若全局关则提示开启)。
- 来源条与能力条独立：选"云端"+选"识图" 合法组合(云端多模态)。

### 5.4 附件规则路由（P2，N6-13 确定性子集）
```
用户加图片附件 ─→ 自动切「识图」(若当前非识图) + 提示"已切换到识图"
用户加音频附件 ─→ 自动切「听写」 + 提示"已切换到听写"
(纯规则, 不调模型, 零误判零延迟)
```
- 路由前若生成进行中：先停止再切（避免语义混乱）。
- 若目标能力不可用(缺模型)：附件菜单对应项置灰，不触发路由。
