## 三、产品目标

| 编号 | 目标 | 衡量指标 |
|------|------|---------|
| G1 | **入口收敛**：把 7 个分散入口收敛为 1 个主对话入口 + 少量快捷直达，新用户首屏不再有"选择困难" | 首屏可见入口数从 7 降到 ≤4；新用户首次成功发起对话的路径 ≤2 次点击 |
| G2 | **能力可发现**：所有能力在同一个对话页内可达，不需要退出重进 | 从"通用对话"切换到其他能力 ≤1 次点击，且**不丢失当前会话上下文**（除单轮模式外） |
| G3 | **自定义可控**：Prompt Lab 选项、Agent/Skill 均可由用户增删改并持久化 | 用户可创建 ≥1 个自定义语气选项、可保存 ≥1 个自定义 Agent，重启后保留 |
| G4 | **说明无死角**：任何界面都能就地获得"这东西是干嘛的、怎么用" | 每个一级页面有内嵌帮助入口；帮助中心覆盖 100% 一级功能（含实验室项） |
| G5 | **为商业化留位置**：不开发重功能，但结构与槽位预留 | 精选推荐位、Feature Flag 表、能力市场数据结构各就位（默认不显示） |

## 四、核心用户场景

| 场景 | 描述 |
|------|------|
| S1 新用户首启 | 装上 Encourage，首屏只看到"开始对话"一个大按钮和一句说明。点进去就能打字聊天，不需要先理解"AI Chat / Prompt Lab / Ask Image 有什么区别" |
| S2 多能力连续使用 | 用户在一次会话里先文字提问 → 拍张图追问"这上面写了什么" → 录一段语音让它整理 → 让它"把这结果总结成三条要点"。全程不退出对话页，只在底部切换能力 |
| S3 老用户肌肉记忆 | 用了三个月的用户，习惯直接点"识图"。首页保留 3 个高频快捷直达，不必每次都从统一入口走两步 |
| S4 重度用户自定义 | 用户想把"语气：高亢"加进快捷任务的语气选项，想在代码生成里加 Rust，想把公司内部的 Agent 配方导入进来用 |
| S5 隐私敏感用户 | 用户担心联网。任何涉及联网的操作（下载 Skill、调用云端 API）都有醒目的首次提示和全局开关，且默认关闭 |

## 五、用户故事

### 5.1 统一入口整合

- **US-1**：作为**首次使用 Encourage 的新用户**，我想打开应用就能直接开始对话，而不是先在一堆功能卡片里做选择，因为我不理解这些专业名词的区别，选错会让我觉得这个软件很难用。
- **US-2**：作为**在一次会话中需要多种能力的用户**，我想在同一个对话页里切换"识图 / 听写 / 快捷任务"，因为我不想为了换个输入方式就退出当前对话、丢失上下文。
- **US-3**：作为**经常只用某一个功能的用户**，我想在首页保留常用功能的快捷直达，因为每次都从统一入口多走一步会让我觉得变麻烦了。
- **US-4**：作为**使用中文的用户**，我希望能力切换的提示和说明都是准确的中文，因为机翻术语会让我不确定点了会发生什么。

### 5.2 导航抽屉扩展

- **US-5**：作为**功能越用越多的用户**，我想在抽屉里按"常用 / 智能 / 系统"分组找到所有功能，因为线性排列的 10 个入口会让我找不到想去的页面。
- **US-6**：作为**想管理 Agent 和 Skill 的用户**，我想在抽屉里有明确的「智能体 / 技能」入口，因为现在它们藏在对话页内部，我根本不知道有这个功能。

### 5.3 Prompt Lab 自定义

- **US-7**：作为**有固定写作风格需求的用户**，我想在"语气改写"里添加自定义的语气（如"高亢""毒舌""学术"），因为内置的 4 个选项覆盖不了我的实际用法。
- **US-8**：作为**经常做文本摘要的用户**，我想自定义摘要的样式和长度（如"三条要点 / 一句话 / 表格化"），因为内置样式太单一。
- **US-9**：作为**写多种语言代码的开发者**，我想在代码生成里添加内置列表没有的语言，并调整输出要求（如"带注释""只要函数体"），因为内置语言列表不全。
- **US-10**：作为**反复使用同一套配置的用户**，我想把调好的选项组合保存为"我的模板"并一键调用，因为每次重选很浪费时间。

### 5.4 Agent / Skill 自定义与联网获取

- **US-11**：作为**想理解 Agent 是什么的用户**，我想看到一个说明，告诉我 Agent 和直接用 AI 对话有什么区别、什么情况下该用它，因为现在的入口什么都没解释，我不知道点进去要干嘛。
- **US-12**：作为**想打造个人助手的用户**，我想新建并编辑自己的 Agent（名字、人设提示词、启用哪些技能），因为内置 Agent 不符合我的场景。
- **US-13**：作为**想用社区现成 Skill 的用户**，我想从 URL 或 GitHub 链接导入 Skill，并在导入前看到它"会做什么、需要什么权限"，因为盲目导入我不放心。
- **US-14**：作为**注重隐私的用户**，我想在导入网络 Skill 时看到明确的联网提示，并能一键关闭所有联网获取能力，因为端侧隐私是我用这个软件的首要原因。

### 5.5 使用说明体系

- **US-15**：作为**第一次打开某个功能页的用户**，我想在该页面就地看到"这是什么、怎么用"的简短说明，因为跳到帮助中心再找会打断我的操作。
- **US-16**：作为**遇到陌生术语的用户**，我想点击参数或选项旁的 "?" 看到通俗解释，因为"Top-K""温度"这类词我看不懂。
- **US-17**：作为**想系统了解软件的用户**，我想在帮助中心看到按模块组织的完整说明，因为我想知道这个软件到底能做什么。
- **US-18**：作为**中英双语使用者**，我希望所有说明都有完整的中英文版本，因为我要把这个软件推荐给外国同事。

## 六、统一入口信息架构方案（重点）

### 6.1 三个候选方案对比

| 维度 | A. 统一对话页 + 能力自动路由 | B. 统一对话入口 + 二级能力选择器 | C. 保留分类但重排 |
|------|------------------------------|----------------------------------|-------------------|
| **做法** | 一个对话页，用户输入后由端侧模型做意图识别，自动分发到对应能力 | 一个对话页，进入后用户在输入区上方**手动选择**当前能力（Chip），选择后进对话 | 不做自动路由，把 8 个入口重排成 3~4 个大类卡片，点卡片直达原页面 |
| **端侧可行性** | ⚠️ **低**。Gemma 4 E2B 做 8 类意图分类，中文短指令准确率无保障；每次输入额外跑一次分类推理，**首 token 延迟 +1~2 秒**（端侧这是显著体验损失）；若改用云端模型路由则违背"离线可用 + 端侧隐私"核心卖点 | ✅ **高**。纯 UI 层切换 `taskId`，不增加任何推理开销，复用现有 7 个 TaskModule | ✅ **高**。改动最小 |
| **误判成本** | ❌ **高**。把"帮我看看这段话"误判为识图，用户需要手动纠正，反而多一步；且误判不可预测、离线难调试 | ✅ **零**。用户显式选择，所见即所得 | ✅ **无路由，无误判** |
| **入口收敛效果** | ✅ 最彻底（1 个入口） | ✅ 彻底（1 个主入口 + 可选快捷直达） | ❌ 不彻底，仍有 3~4 个平铺入口，新用户依旧有选择困难 |
| **依赖特定模型能力** | ❌ 需路由模型常驻内存，与 LLM 抢 NPU 内存 | ✅ 无额外模型依赖。Mobile Actions / Tiny Garden 依赖 FunctionGemma，可通过"能力不可用时置灰 + 说明原因"处理 | ✅ 同 B |
| **中英双语** | ❌ 路由提示词需要中英两套并分别调，维护成本高 | ✅ 只是文案翻译，无逻辑差异 | ✅ 同 B |
| **离线可用性** | ⚠️ 依赖模型质量，离线时降级方案复杂 | ✅ 100% 离线可用 | ✅ 100% 离线可用 |
| **开发工作量** | 大（中→大，且调优是无底洞） | 中→大（主要是 UI 层重构 + 7 个 TaskModule 适配） | 小 |
| **可解释性** | ❌ 用户不知道为什么被路由到某能力 | ✅ 用户全程知道自己在用什么能力 | ✅ 明确 |
| **商业化预留** | 弱 | ✅ 强（能力选择器可加"推荐/精选"槽位） | 中 |

### 6.2 推荐方案：**B+（B 为主干 + C 的快捷直达 + A 的确定性子集）**

**一句话理由**：在端侧算力受限、离线是核心卖点的前提下，把"理解用户意图"这件不可靠的事交给人（一次点击），把算力全部留给真正生成内容——B 是唯一同时满足"入口彻底收敛""零误判""100% 离线""无额外推理开销"的方案。

#### B+ 的三层结构

```
首页 Home
  ├─ 主入口：开始对话（大按钮，唯一视觉焦点）
  ├─ 快捷直达（3 个，保留 C 的价值：老用户肌肉记忆 + 商业化推荐位）
  │    ├─ 识图
  │    ├─ 听写
  │    └─ 快捷任务（原 Prompt Lab）
  └─ 实验室（折叠容器，见第 7 章）

        │ 点击任一入口
        ▼
统一对话页 UnifiedChatScreen（唯一对话容器）
  ├─ 顶部：M7 推理来源条（自动 / 本地 / 云端）        ← 复用，不改
  ├─ 中部：消息列表（沿用 ChatView）
  └─ 输入区上方：能力选择器 CapabilityBar（横向 Chip）
        ├─ 通用对话（默认）
        ├─ 识图
        ├─ 听写
        ├─ 快捷任务（单轮模式，带模板选择器）
        ├─ 智能体（选择 Agent + Skill）
        └─ 更多（实验室能力入口）

        │ 附件确定性规则（A 的零误判子集，P2）
        ▼
  用户添加图片附件 → 自动切到「识图」
  用户添加音频附件 → 自动切到「听写」
  （纯规则，不调用模型，零误判、零延迟）
```

#### 为什么保留 C 的快捷直达（而不是纯 B）

1. **老用户肌肉记忆**：识图 / 听写是高频刚需，让用户每次多走一层是体验倒退。
2. **商业化预留位**：快捷直达区天然是"推荐能力"的展示位（见第 12 章）。
3. **首屏不能只有一个按钮**：纯 B 的首屏过于空旷，无法承载"这个软件能做什么"的信息传达（对 G1 有反作用）。

#### 为什么只取 A 的"附件规则路由"子集

- 图片/音频附件的路由是**确定性规则**（有图必走识图），不存在误判，也不需要额外推理。
- 真正的语义意图路由（"帮我看看这个"到底指图还是指文字）**本期不做**，列为 P2，等端侧模型能力增强或云端路由方案成熟后再评估。

### 6.3 8 个入口的收敛映射表

| 原入口（BuiltInTaskId） | 收敛去向 | 处理方式 |
|------------------------|---------|---------|
| `LLM_CHAT` | 统一对话 · **通用对话**（默认能力） | 作为统一对话页的默认状态，保留全部现有能力（多轮、附件、系统提示词） |
| `LLM_ASK_IMAGE` | 统一对话 · **识图**能力 + 首页快捷直达 | 改为能力 Chip；保留附件自动切换规则 |
| `LLM_ASK_AUDIO` | 统一对话 · **听写**能力 + 首页快捷直达 | 同上 |
| `LLM_PROMPT_LAB` | 统一对话 · **快捷任务**能力（单轮模式）+ 首页快捷直达 | 单轮模式 = 不保留上下文，输入/输出分栏；模板选择器并入能力面板 |
| `LLM_AGENT_CHAT` | 统一对话 · **智能体**能力 | 选择 Agent + 启用 Skill 后进入对话；入口同时进抽屉 |
| `LLM_MOBILE_ACTIONS` | **实验室**（折叠） | 依赖 FunctionGemma 270m，先讲明用途再决定（见第 7 章） |
| `LLM_TINY_GARDEN` | **实验室**（折叠） | 模型无法下载，先讲明用途再决定（见第 7 章） |
| `MP_SCRAPBOOK` | **删除或转为占位** | 死代码，无任何 TaskModule 注册（见 Q2） |

**净效果**：首屏可见入口 7 → 4（主入口 + 3 快捷），全部能力在 1 个对话页内可达。

### 6.4 关键交互规则

| 规则 | 说明 |
|------|------|
| 切换能力不丢上下文 | 除「快捷任务」（单轮模式）外，切换能力**保留当前会话消息**；切换到单轮模式时提示"单轮模式不会保留上下文" |
| 能力不可用时的处理 | 依赖模型未下载的能力（智能体需 FunctionGemma、识图需多模态模型）**置灰 + 气泡说明原因 + 一键跳转模型管理下载**，不静默禁用 |
| 默认能力记住 | 记住用户上次选择的能力，下次进入默认选中（通用对话为出厂默认） |
| 来源条与能力条共存 | 顶部来源条（M7）与底部能力条各司其职；来源条仅在配置了云端 API 时显示（沿用 M7 逻辑） |

## 七、Mobile Actions 与 Tiny Garden：讲明用途 + 处理建议

> 用户此前表态"不清楚用途，讲明后再决定扩展"。本章即为**讲明**部分，PRD 不替用户做决定，只给建议。

### 7.1 Mobile Actions（现名建议：**语音指令 / 手机操控**）

**它是什么**：一个跑在手机本地的"自然语言操控手机"功能。你用中文说一句话，端侧小模型把这句话翻译成一个手机操作指令并执行。

**依赖条件**：
- 需单独下载 **FunctionGemma-270m** 模型（约 270M 参数，体积数百 MB）
- 部分操作（如模拟点击、自动填写）需要 **Android 无障碍权限**
- 完全离线，不联网

**能做什么（示例）**：
| 你说 | 它做 |
|------|------|
| "打开手电筒" | 调用系统 Intent 打开手电筒 |
| "把亮度调低一点" | 调整屏幕亮度 |
| "帮我定明天早上八点的闹钟" | 创建系统闹钟 |
| "打开微信" | 启动微信 |

**不能做什么**：不能操作第三方 App 内部界面（如"帮我在淘宝下单"），受 Android 沙箱与权限限制。

**实际价值**：与已完成的**定时任务（E 类）天然互补**——定时任务触发时可以执行手机操作，这是同类端侧 AI 应用中少见的差异化能力。

**风险**：中文指令识别准确率未经实测验证；国产 ROM 对无障碍权限的限制可能导致功能不稳定。

**处理建议（三选一）**：

| 方案 | 说明 | 评价 |
|------|------|------|
| **① 保留并讲明（推荐）** | 移入「实验室」，配一段 100 字用途说明 + 3 个示例 + 一键下载 FunctionGemma 按钮 | ✅ 成本最低，保留差异化卖点，用户可自行判断是否值得 |
| ② 保留并增强 | 在①基础上做中文指令调优与定时任务联动 | ⚠️ 中工作量，建议先做完①看用户反馈 |
| ③ 砍掉 | 移除入口与代码 | ❌ 会损失一个潜在的差异化能力，且 M0~M5 已为其做过模型过滤器适配 |

### 7.2 Tiny Garden（现名建议：**AI 小花园**）

**它是什么**：一个用自然语言玩种花小游戏的演示 Demo——你说"种一朵红色的花"，端侧模型把它翻译成游戏指令，花园里就长出一朵花。

**依赖条件**：同样依赖 **FunctionGemma-270m**，且**目前该模型在国内网络环境下无法下载**，所以这个功能现在是**点了也用不了的死入口**。

**它的真实定位**：这是 Google 用来**演示 Function Calling 能力**的玩具 Demo，不是正经功能。对普通用户而言，玩两分钟新鲜感过后没有留存价值。

**处理建议（四选一）**：

| 方案 | 说明 | 评价 |
|------|------|------|
| **① 移入实验室 + 标注"演示功能、需下载模型"（推荐）** | 讲明它是演示 Demo，不承诺可用性 | ✅ 诚实、成本为零，用户自己决定 |
| ② 国产化复活 | 接入支持 Function Calling 的国产小模型（如 Qwen2.5-0.5B LiteRT 转换版）替代 FunctionGemma | ⚠️ 大工作量，且要验证国产小模型的 Function Calling 质量。文档 05 曾建议此方案，但从投入产出比看**不推荐优先做** |
| ③ 改造为其他场景的 Playground | 把游戏逻辑替换成定时任务/自动化的演示场景 | ⚠️ 中工作量，定位尴尬 |
| ④ 砍掉 | 移除入口 | ✅ 可接受。若用户认为"演示 Demo 没有价值"，砍掉最干净 |

**PM 建议**：**① + 视反馈决定是否 ④**。它是一个"证明端侧模型能调用工具"的活的说明书，放在实验室里讲清楚，比砍掉更有信息价值；但不要为它投入国产化改造成本（② 的投入产出比在所有候选项中最低）。

### 7.3 实验室（Lab）容器设计

两个待定项统一放进「实验室」：
- 位于首页底部折叠区 + 抽屉「系统」组
- 每个实验室项必须显示：**用途一句话说明 + 依赖条件 + 当前可用性状态 + 一键处理（下载模型/移除）**
- 实验室项默认**不出现在能力选择器主行**，需点「更多」展开

## 九、Prompt Lab（快捷任务）自定义

### 9.1 现状问题

1. 只有 4 个模板页（Free form / Rewrite tone / Summarize / Code snippet）
2. **选项写死**：语气只有内置几项，不能加"高亢"
3. 摘要样式、代码语言选项太少

### 9.2 改进设计

**核心机制：选项组（OptionGroup）可配置化**

```
每个模板定义 → 若干选项组 → 每个选项组 = 内置选项 + 用户自定义选项
自定义选项持久化到 DataStore（proto 新增字段）
```

| 模板 | 现有选项 | 自定义支持 |
|------|---------|-----------|
| 自由模式 | 无 | 可保存自定义提示词片段 |
| 语气改写 | Tone（正式/随意/友好…） | ✅ 增删语气值，如"高亢""毒舌""学术""可爱" |
| 文本摘要 | Style（要点列表/短段落/精简摘要） | ✅ 增删样式 + **新增"长度"维度**（一句话 / 三段 / 详细）+ **"格式"维度**（纯文本 / Markdown 表格） |
| 代码生成 | Language（Python/C++/Kotlin…） | ✅ 增删语言 + **新增"输出要求"维度**（带注释 / 只要函数体 / 含单元测试 / 指定代码风格） |

**配套能力**：
- 每个选项组有"+ 自定义"入口，弹出输入框（中英双语输入）
- 自定义项可删除、可恢复默认
- **模板组合可保存为"我的模板"**（名称 + 所选选项快照），首页快捷直达区可调
- 提供"预览完整提示词"（现有功能保留），让用户看到自定义后的真实 Prompt

### 9.3 数据结构建议（给架构师参考）

```kotlin
data class PromptOptionGroup(
  val id: String,              // "tone" / "summary_style" / "code_language"
  val labelRes: Int,           // 中文/英文字符串
  val builtInOptions: List<PromptOption>,
  val customOptions: List<PromptOption>,   // 持久化
  val allowCustom: Boolean = true,
)

data class PromptOption(val id: String, val label: String, val promptFragment: String)

data class SavedTemplate(
  val id: String, val name: String, val templateId: String,
  val selectedOptions: Map<String, String>,
)
```

> 持久化建议存 `settings.proto`（已有 DataStore 基础设施），避免引入新存储层。

## 十、Agent / Skill 自定义与联网获取

### 10.1 现状问题（用户反馈）

1. **使用逻辑不清楚**：用户不知道 Agent 是什么、和直接对话有什么区别
2. **不能自定义**：M5 的 AgentManager 支持"查看 + 应用内置 Agent"，但**不能新建/编辑**
3. **不能下载网络 Skill**：M5 只做了本地能力暴露（`/v1/skills`），没有做网络取回

### 10.2 改进设计

#### （1）先解决"不清楚"——Agent 是什么

在智能体能力入口处提供一段**通俗说明**（进帮助中心可展开全文）：

> **Agent（智能体）是什么？**
> 普通对话 = 你和 AI 直接聊天。
> 智能体 = 你先给 AI 设定一套"人设 + 可用工具"，然后在这套设定下聊天。
> 举例：选一个"英语翻译官"智能体，它每次回复都会自动按翻译官的角色处理，不用你每次重复说明。
> **什么时候用？** 当你发现自己每次都在重复同一段说明时，就把它存成一个智能体。

#### （2）自定义 Agent（P1）

| 能力 | 说明 |
|------|------|
| 新建 | 名称、人设提示词（多行输入）、启用的 Skill 勾选、图标 |
| 编辑 | 内置 Agent **只读**（防误改），但可"复制为我的"后编辑 |
| 删除 | 仅用户自建可删 |
| 导入/导出 | 导出为 `.json` 文件（走文件管理器），可分享给他人 |
| 来源标识 | 徽标区分：内置 / 用户自建 / 网络导入 |

#### （3）Skill 联网获取（P1，需用户拍板）

**三步式导入流程（每步都可见、可中止）**：

```
① 输入来源（URL / GitHub 仓库链接 / 精选列表点选）
        ▼
② 预览与审阅（关键：先看后装）
   - 名称、描述
   - 【能力清单】这个 Skill 会做什么（调用哪些工具）
   - 【权限声明】需要联网吗？会读文件吗？会执行操作吗？
   - 【来源信息】作者、链接、文件大小
        ▼
③ 确认导入（首次导入弹出联网授权提示）
   - 明确告知"此操作将联网下载"
   - 提供全局开关"允许从网络获取技能"（默认关闭）
```

**安全与隐私设计（硬性要求）**：
- 网络来源的 Skill 默认**限制敏感工具**（文件写入、手机操作、联网）
- 导入后 Skill 文件落在独立目录 `skills/network/`，与内置 `skills/builtin/`、用户 `skills/local/` 分离
- 每个 Skill 卡片显示来源徽标，网络来源可一键卸载
- **全局开关 + 首次提示**（沿用文档 05 已确认的联网提示策略）

#### （4）精选列表（商业化预留位，P1）

- 本地 `assets/skill_registry.json` 维护精选 Skill 列表（无需后端）
- 列表项：名称、描述、作者、下载链接、分类标签、**`featured` 推荐字段（预留）**
- 全部走上述三步式导入流程，不做静默安装

### 11.1 三层结构

|------|------|

### 11.3 首启引导（Onboarding）

用户原话："如果足够自信可以让使用说明简化，因为大多软件操作手法、使用逻辑是一样的。"

**采纳**：不做长篇引导，做 **3 步卡片式**（≤10 秒读完），且**可跳过**、**仅首次启动显示**：

1. **说人话就行** —— 打开就能打字聊天，本地运行，不联网
2. **换能力在底部** —— 想识图/听写/快捷任务，点输入区上方的标签
3. **想深入看这里** —— 抽屉里有说明、模型和设置

> 每步一图一句，第 3 步带"查看完整说明"按钮跳帮助中心。

### 11.4 文案原则

| 原则 | 说明 |
|------|------|
| 说人话 | 禁止"推理""推理后端""Token 预算"等术语直接暴露给用户；必须用时括注解释 |

| 中英同源 | 所有说明文案必须中英双版本同步提交，禁止只写中文 |
| 不重复 | 同一句话只在最相关的一层出现（L1 说了 L3 就不再重复整段） |

### 14.2 P1 首页 Home（收敛后）

**核心任务句**：
> 一位**刚装上 Encourage 的新用户**，在**第一次打开应用**的场景下，需要**立刻知道这个软件能做什么并开始第一次对话**，因为**我们要把"从打开到首次成功对话"的时间压到最短，降低新用户流失**。

**信息优先级**：
| 层级 | 内容 | 说明 |
|------|------|------|
| L1（最重要） | 「开始对话」主入口（大按钮/大卡片） | 唯一视觉焦点，占据首屏黄金位 |
| L1 | 一句话产品说明 | 现有 `app_intro` 位置，需改写为 Encourage 口吻（例："完全本地运行的 AI 助手，不联网也能用"） |
| L2 | 3 个快捷直达（识图 / 听写 / 快捷任务） | 横向三等分小卡片，图标 + 4 字以内标签 |
| L2 | 使用说明入口卡（`HomeHelpCard` 已有，需强化） | 现有组件改造，文案改为"查看使用说明" |
| L3 | 「实验室」折叠区（默认收起） | 底部，标题旁有"实验性"徽标 |
| L3 | 全部能力（现有分类 Tab + ViewPager 保留，可下移或收纳进"更多"） | 老用户找长尾入口的通道 |

**关键状态**：
| 状态 | 设计要点 |
|------|---------|
| 空（首次启动，无模型） | 主入口按钮显示"先下载模型"，点击跳模型管理；说明文案提示"首次使用需下载一个模型（约 X GB）" |

| 无权限 | 无（首页不依赖特殊权限） |

### 14.3 P2 统一对话页 UnifiedChatScreen

**核心任务句**：
> 一位**需要在一次会话中混用多种能力的用户**，在**先文字提问、再发图追问、最后让它总结**的场景下，需要**在同一个页面内完成全部操作而不丢失上下文**，因为**频繁退出重进是这类应用最大的体验痛点**。

**信息优先级**：
| 层级 | 内容 |
|------|------|
| L1 | 消息列表（沿用现有 ChatView，不改） |
| L1 | 输入框 + 发送按钮 |
| L2 | **能力选择器**（输入区上方，横向 Chip） |
| L2 | M7 推理来源条（顶部，仅配置云端时显示） |
| L3 | 附件按钮（图片/音频/拍照，沿用现有） |
| L3 | M7 生成统计条（生成完成后显示） |
| L3 | 右上角：会话历史、配置（沿用现有） |

**关键状态**：
| 状态 | 设计要点 |
|------|---------|
| 空（新会话） | 中央显示当前能力的引导语（如"识图：发一张图片，问我任何关于它的问题"），随能力切换变化 |
| 加载（生成中） | 沿用现有流式渲染 + 停止按钮；能力 Chip 置灰不可切换（避免中途切能力导致语义混乱） |
| 错误 | 沿用现有错误气泡；**新增：能力依赖模型缺失时 → Chip 置灰 + 气泡说明 + 「下载模型」按钮** |
| 成功 | 沿用 M7 统计条 |
| 无权限（录音/相册） | 沿用现有权限申请流程；被拒后附件菜单对应项置灰 + 说明"需要相册权限，去设置开启" |

**能力选择器设计要求**（P3 组件，重点）：
- 横向滚动 Chip 组，当前选中高亮
- 每行最多显示 5 个，第 6 个为「更多」（打开底部面板展示实验室能力与全部能力）
- 不可用的能力 Chip **置灰 + 右上角小锁图标**，点击弹出说明气泡
- 切到「快捷任务」时，页面切换为**单轮分栏模式**（上输入、下输出），需**明确提示"此模式不保留上下文"**
- Chip 文案中英均需 ≤6 字（中文）/ ≤14 字符（英文），超出需设计省略与完整显示方案

### 14.4 P4 快捷任务面板（原 Prompt Lab）+ 自定义选项编辑器

**核心任务句**：
> 一位**有固定风格需求的内容创作者**，在**反复使用同一种改写风格**的场景下，需要**把自己常用的语气、摘要样式、代码输出要求固化下来反复调用**，因为**每次重选选项的时间成本会让他放弃使用这个功能**。

**信息优先级**：
| 层级 | 内容 |
|------|------|

| L1 | 输入区 / 输出区（单轮分栏，沿用现有 `VerticalSplitView`） |
| L2 | 选项组（语气 / 样式 / 长度 / 语言 / 输出要求…） |
| L2 | 「+ 自定义」入口（每个选项组尾部） |
| L3 | 「预览完整提示词」「保存为我的模板」 |
| L3 | 我的模板列表（折叠或抽屉内） |

**关键状态**：
| 状态 | 设计要点 |
|------|---------|
| 空（无自定义项） | 选项组尾部显示「+ 自定义」虚线按钮，下方灰字"添加你自己的选项" |
| 加载（推理中） | 输出区显示进度 + 停止按钮 |

**自定义选项编辑器设计要点**：

### 14.9 P9 首启 3 步引导 Onboarding

**核心任务句**：
> 一位**第一次打开 Encourage 的新用户**，在**启动后的前 10 秒**的场景下，需要**用最短时间理解"怎么开始用"**，因为**过长的引导会被跳过，等于没做**。

**设计约束（硬性）**：
- **最多 3 步**，每步：一图 + 一句（≤15 字）+ 一句补充（可选）
- **可跳过**（右上角"跳过"，全程可见）
- **仅首次启动显示**，之后不再出现（设置里可重新打开）
- 第 3 步带「查看完整说明」按钮 → 帮助中心
- 完成后直接进入首页，不额外插页

**三步内容**：
1. 说人话就行 —— 打开就能打字聊天，本地运行不联网
2. 换能力在底部 —— 识图/听写/快捷任务，点输入区上方标签
3. 想深入看这里 —— 抽屉里有说明、模型和设置

**关键状态**：
| 状态 | 设计要点 |
|------|---------|
| 空 | 无 |
| 加载 | 无（本地静态） |
| 错误 | 无 |
| 中途退出 | 下次启动从头开始（或记录进度，见 Q6） |

### 14.11 P11 Skill 导入预览与授权弹窗（P1）

**核心任务句**：
> 一位**想从网络获取现成技能的用户**，在**点击导入之前**的场景下，需要**看清这个技能会做什么、需要什么权限、来自哪里**，因为**端侧隐私是他使用本软件的首要原因，盲目导入会摧毁信任**。

**信息优先级**（预览弹窗内）：
| 层级 | 内容 |
|------|------|
| L1 | 技能名称 + 一句话描述 |
| L1 | **能力清单**（会做什么） |
| L1 | **权限声明**（联网？读文件？执行操作？）→ 每条带图标，敏感项高亮 |
| L2 | 来源信息（作者、链接、大小） |
| L3 | 底部：「取消」「确认导入」 |

**关键状态**：
| 状态 | 设计要点 |
|------|---------|
| 加载（获取预览中） | 进度 + 取消 |
| 错误（链接失效/格式错误） | 明确原因 + 建议（"换个来源试试"） |
| **首次联网提示** | 独立弹窗：标题"此操作将联网"+ 说明"下载的技能来自第三方，我们将…" + 全局开关"允许从网络获取技能"（默认**关闭**）+ 「取消」「我知道了，继续」 |
| 无网络 | 明确提示 + 「查看本地已有技能」 |
| 权限过高（需敏感工具） | 权限声明区红色高亮 + 需用户额外勾选确认才可继续 |

### 14.12 P12 联网首次提示弹窗 + 全局开关（P1）

**核心任务句**：
> 一位**因为"完全本地、不联网"才安装 Encourage 的用户**，在**某功能首次尝试联网**的场景下，需要**被明确告知并拥有否决权**，因为**任何静默联网都会直接摧毁产品的核心信任**。

**设计要求（硬性）**：
- 全局开关位于**设置页顶部醒目位置**，默认 **关闭**
- 首次联网操作弹窗，**每次新类型的联网操作各提示一次**（下载 Skill / 调用云端 API 分开记）
- 弹窗文案必须包含：① 什么操作要联网 ② 会传什么数据 ③ 不开启会怎样
- 弹窗必须有「取消」，且取消后功能可用降级方案时给出降级路径
- **禁止**使用暗黑模式（dark pattern）：不得把"允许"做得比"取消"更醒目

### 风险

| # | 风险 | 影响 | 建议 |
|---|------|------|------|
| R1 | **任务书与代码不一致**（抽屉、帮助中心、首页顶部其实都已部分完成） | 若按旧描述开发，会造成重复劳动与返工 | 开发前以第 2 章校正表为准；建议把 `04_界面与操作流程.md` 更新为当前真实状态（本文档可作为更新依据） |

| R5 | **帮助文案写完就过期**：N6 之后还有新功能，说明体系会腐化 | 说明与功能不符，反而误导 | 建议把"更新对应帮助章节"写进每个迭代的 Definition of Done |

## 十七、验收标准（草案）

| 维度 | 标准 |
